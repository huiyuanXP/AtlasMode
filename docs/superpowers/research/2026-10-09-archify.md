## 结论

Archify 的 hover 高亮、点击详情卡、卡片关系行与画布的双向联动很适合参考。它不是可直接导入的 React/React Flow 组件库，而是离线独立 SVG + 原生 DOM/CSS/经典脚本生成模板。建议保留 AtlasMode 的 React Flow、真实索引与现有双击漏斗，用本地 React 状态实现相同交互规则；借用小段图标/样式时保留 MIT 来源说明。不要把完整模板、DOM 查询 IIFE 或静态 JSON 模型直接嵌入产品。

## AtlasMode 计划建议（供用户先评审）

1. 先采用 hover 轻预览、单击锁定选择+详情、双击保留现有漏斗。高亮只改变颜色/透明度，不改布局、分页、图数据与规划 revision；hover 不触发 camera，不打开详情。路线/漏斗期间明确谁拥有高亮，减少互相覆盖。
2. DetailCard 使用 AtlasMode 真实字段：名称/签名、文件与可复制行位置、关系方向与数量、事实/规划来源、unresolved 提示。隐藏缺失字段；不要复制 Archify 的 verified badge 到未具备同样证据的静态调用上。
3. 关系行 hover 高亮唯一 edge 与两个端点，点击跳转邻居；关系数量多时沿用已存在分页/预算。可把同一状态投影到图、详情与小地图；源代码面板按显式动作打开。
4. 小地图复用 React Flow MiniMap 能力（本项目已有）并统一 selected/kind 样式，参考 Archify 的 viewport/current selection/避让规则；不移植 getBBox 原生 radar。图标优先统一现有 SVG 图标系统；若直接复用 Archify 的几个布局 glyph，应带来源说明。
5. 保留用户当前选中的局部图和手动布局，关系切换只做现有 camera reveal。Archify 的 repeat-click toggle/clear resetView 是上游选择，AtlasMode 是否重复点击关闭以及关闭后是否还原图，应按本项目当前交互决定，不能机械照搬。
