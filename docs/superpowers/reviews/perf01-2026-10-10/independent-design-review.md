## I1 — root ownership is not yet part of the executable candidate validation protocol

**Important. Locations:** spec lines 29–35, 39, 51, 57–61, 75, 84–86; plan tasks 2–4, especially lines 92–106 and 116–118.

The design correctly requires a WatchSession to belong to its original canonical root/root identity and to stop rather than silently attach old knowledge to a replacement directory (spec 51). However, the specified completion witness in spec 35 is source/config/package bytes, exclusions, availability and diagnostics; the plan's second-capture test changes source bytes. It does not explicitly carry the session's expected root identity through both captures and into the lock-held publication check. An epoch only changes after something notices the replacement; the new cache key alone prevents AST reuse and does not prevent publishing a replacement root under the existing path-derived project ID.

The current `scan.ts` confirms why this needs a new internal contract: `rootDirectory` obtains `realpath` and checks directory type, and `scan` returns the canonical root string, but it does not return a root identity witness. `WorkspaceService` derives project ID from the supplied absolute path. Thus the existing capture interface cannot independently establish continuity of the originally owned directory.

**Concrete failing design interleaving:** an automatic invocation is admitted for owned root A, analysis is paused, and the same canonical path is replaced with directory B containing identical captured bytes/config/inventory. A missing/delayed root watch event leaves the session epoch unchanged. A second capture can have exactly the listed input witness while observing B. Checking ownership only at session creation or job admission, or merely calculating a new cache key, would accept the candidate and update the old project's snapshot/knowledge. A retargeted root alias creates the analogous canonical-root case. This is a missing design requirement; no product reproduction was run or claimed.

**Required narrow repair:** define a private root ownership witness and its lifecycle. Each capture must prove it belongs to the admitted WatchSession's expected canonical root and reliable root identity; compare the first and second capture to that same expected owner, and validate the currently observed owner again at the lock-held publication handoff. If identity is unavailable, lost or changed, discard the candidate/cache, invalidate the session, expose `root_changed`, and leave snapshot pointer, knowledge/revisions/history unchanged. The full fallback must not bypass this guard or establish a replacement owner automatically. Specify that the existing stopped session remains stopped and only the already-required explicit path-confirmed reopen can establish a new session; ordinary background reconciliation must not do so.

Add owned, real-filesystem barrier fixtures that replace a root with identical bytes during analysis, retarget a root alias, and replace the root after analysis but before publication, while suppressing/delaying watcher hints. Assert no original-project snapshot publication, no knowledge/invalidation change, no cache/session revival, and the expected stopped/error status. Keep native-platform identity availability a real acceptance condition. This requires fail-closed handling of observed ownership changes; it does **not** demand an atomic filesystem snapshot or an impossible guarantee against an unobserved change immediately after the final check.

[Node's official watcher caveats](https://nodejs.org/docs/latest-v24.x/api/fs.html#inodes) explain that Linux/macOS watchers remain attached to the old inode after deletion/recreation, and filename/event delivery cannot establish directory identity. The event-plus-periodic-capture approach is sound only when capture validates the session owner as well as its bytes.

## Passed design areas to preserve during repair

- **Mutable AST and semantic isolation:** spec 39–47 and tasks 1–2 require context/authorization/compiler options and captured module conditions, honor `shouldCreateNewSourceFile`, discard reuse when context comparison is uncertain, and create a fresh resolver/checker and analyzer maps. Installed TypeScript 5.9.3 really mutates SourceFile package/path state in `tryReuseStructureFromOldProgram` and keeps non-transient node/symbol links in checker-owned tables. Its actual host declarations and reuse branches support the proposed invalidated-resolution mechanism. Full semantic/call/veto traversal is required even for unchanged importer text. The design does not call ASTs immutable or claim all binder work reruns. The [official Compiler API guide](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API#writing-an-incremental-program-watcher) distinguishes ordinary Programs from builders that cache semantic diagnostics; implementation must still prove the custom captured host matches the frozen full builder.
- **Full oracle and conservative fallback:** full bypasses all Program cache; analysis reads captured bytes only; unknown/partial authorization stays conservative. Exact comparisons retain node/relation array order and IDs, all diagnostics and coverage/configuration graph fields, with only `createdAt` omitted. This matches the actual Graph relation ordinal identity. Config/package/reference/module/ignore changes, unknown events and cache failure fall back without granting extra authorization. Direct-call concurrency, cache generation, eviction and abort ownership have named future tests.
- **Owned scheduling and stop:** events are hints, inventory reconciliation remains complete, attach-gap reconciliation and periodic polling are required, hint capacity/debounce/max wait are finite, and one automatic ticket plus one dirty follow-up uses the existing project queue. Manual requests precede a later follow-up. Stop fences queued and running automatic publication while preserving manual refresh, and does not silently restart on open. The root repair must preserve these constraints.
- **Closing/storage:** the proposal acknowledges that current server `shutdown` closes storage in a `finally` after `app.close`, and that current StructureSync has no admission-close/drain API. Future close must synchronously fence admission, track dispatched raw work, abort owned index/Python work, keep truthful pending state when a deadline expires, and close storage only after actual idle. Synchronous compiler work is not represented as physically preemptible. This is conditional on the AG03 shared owner lifecycle and main-controlled shared-file window; those interfaces are not asserted to exist now. No second registry or independent publication queue is approved.
- **Knowledge/Plan preservation:** spec 75 and task 4 explicitly depend on the final KN/POL joint contract. Current source snapshot reconciliation and structure freshness are sequential, so the future single-invalidation/joint-publication tests are necessary and correctly pending. An unchanged source hash cannot skip structure freshness; old approval/context/history and conservative orphan handling remain protected. No target source write or identity migration is part of this ticket.
- **Actual visible controls and evidence:** status/stop are strict real service/HTTP contracts, with default-off trusted enablement, owned UI polling cancellation and project epochs. A new server snapshot prompts existing full refresh instead of silently replacing a graph/Plan baseline. The planned browser/HTTP/MCP SDK and Linux/macOS/Windows gates are explicit future work. Pure Node/mock fixtures and Linux results cannot be presented as Windows native evidence.
- **Performance honesty:** the Express commit and historical index counts are functional provenance, not a measured PERF result. Five warmups and at least twenty interleaved paired owned-copy samples must include capture, second verification, queue, analysis and storage costs, preserve raw outliers, report p50/p95/RSS/heap and compare the final auto/full result to the original full baseline. The 20% p50 gain and 10% regression limits are proposed acceptance thresholds. No benchmark was run, and missing native/lifecycle/functional/performance gates require PARTIAL rather than DONE.
