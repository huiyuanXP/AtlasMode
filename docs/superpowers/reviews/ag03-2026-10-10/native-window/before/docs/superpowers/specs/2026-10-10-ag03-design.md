# AG03 Windows 原生 Agent 所属 Job 与有限收口设计

日期：2026-10-10。作者执行模型：gpt-6.1-sol high。版本：rev1，仅修独立审查 I1/M1；原 rev0 字节与 REQUEST CHANGES 原文已归档。状态：DESIGN ONLY，等待原 reviewer 复审及主控产品窗口。此文不解除现有 Windows 原生 Chat guard。

## 目标与当前事实

为 Windows 原生 Agent 的每次运行和能力探测建立独立于 CLI 根 PID 的所属 Job。根先退出而 MCP 后代仍持有 stdio 时，仍能终止所属进程、关闭本轮 gateway，并诚实记录已派发写入。HTTP/UI/通用 MCP 既有 Windows 支持保留。

实际票据是 `docs/tickets/AG-03.md`；QA02 的真实 Codex/Claude 接入、交互 Ctrl+C 和历史 SIGKILL 因果证据仍独立未完成。当前 `process.ts`、`native.ts` 的 inspect/start 三处 Windows refusal 不能在本轮设计中删除。

读取实现确认：POSIX runner 用 detached process group；native 的 help/features/login probe 则单独 spawn、仅 kill 根。gateway.close 先 closeAllConnections，再无界等待已 dispatch 的 app.inject；bridge 只有随后才写 journal 与 terminal 状态。服务器 index.shutdown 当前 finally 关闭 storage。`scripts/dev.mjs` 只接受各 prerequisite 的 build 精确等于 `tsc -p tsconfig.json`。这些都是实现必须保留或明确修正的实际契约。

## 范围和选型

选择仓库自有 C++ Win32 helper，以独立进程封装 Job/进程 HANDLE/控制管道；Node 继续负责 JSONL、工具限制和 gateway。目标运行平台为 Windows 10+/Server 2016+ x64；ARM64、x86、旧系统明确 unavailable，不能把 x64 CI 推广为这些平台。

比较过三条路径：PID 树/taskkill 不能保持根退出后的归属；PowerShell 动态编译或新增 N-API 包引入执行策略、ABI、第三方二进制及安装依赖；自有 C++ helper 可以明确审核 Win32 API、继承句柄和编译来源。选第三条。它是待实现候选，当前没有已安装的 Windows helper 或 native gate 收据。

Job 是本轮普通 CreateProcess 后代的资源归属机制，不是对同权限恶意代码的安全沙箱。不开启 BREAKAWAY_OK/SILENT_BREAKAWAY_OK，不使用提权、服务、WMI、全机进程扫描或按名称杀进程；也不声称拦截经系统服务等外部机制创建的进程。保留现有 CLI 工具禁用、临时 cwd、私有配置和 scoped gateway 边界。[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## 分发与二进制 identity

新增 source 位于 `apps/server/native/agent-job/`，构建入口 `scripts/build-agent-job.mjs`，根独立可选命令 `build:agent-job`。现 server `build`、pre/post lifecycle 和 dev 编译白名单保持不变；不在 npm install/ci lifecycle 下载或编译 native helper。

在已配置的 x64 MSVC/Windows SDK 环境使用 `/std:c++20 /MT /W4 /WX /Brepro` 生成 `apps/server/native/bin/win32-x64/atlas-agent-job.exe`；静态 CRT，运行时不要求额外安装 redist。构建脚本拒绝非 Windows/x64、缺编译器或 SDK，不安装软件。Windows CI 用现有 Visual Studio 的 vswhere/VsDevCmd 激活工具链，记录实际版本；runner image 内容会变，不能假设 cl 已在 PATH。[官方 runner image 清单](https://github.com/actions/runner-images/blob/main/images/windows/Windows2025-Readme.md)

同目录 manifest 为 strict JSON：`protocol:1, platform:"win32", arch:"x64", sourceDigest, binarySha256, compiler, sdk`；两个 digest 为 lowercase 64位hex，compiler/sdk 为非空且≤128字符字符串。sourceDigest 是排序后的 helper source/协议定义/构建脚本相对路径与文件 SHA256 的规范摘要，范围写进构建脚本，并与当前checkout的source bytes核对；手动CI artifact必须匹配同一source版本。运行时固定从 server-relative 目录读取，不从 PATH/HTTP/ChatInput 指定 helper；拒绝 symlink/reparse 路径偏离、缺文件、错误类型/未知 key、版本/架构/sourceDigest/二进制 hash 不一致。inspect 和每次 start 都重新验证实际 bytes。manifest 是可复现来源与误配检查，不是抵御同权限恶意替换的签名。

CI 可产出该仓库 commit 对应的 exe+manifest+编译与机制测试 receipts 作为 Actions artifact；发布 Release 或其他公开分发由主控另行授权。用户可以用已有工具链自行编译或手动放置已核验的仓库 CI artifact；无自动下载或未知第三方发行。源码构建应可复现步骤；只有实际两次相同工具链的 binary SHA 相同，才声称 byte-for-byte reproducible。

CLI executable 要求可信绝对路径的实际 `.exe`。拒绝 `.cmd`/`.bat`/PowerShell shim 和 shell fallback，不拼接 shell 字符串。测试用 node.exe 通过，不代表已支持真实 Codex/Claude 的所有发行方式。真实客户端只有解析到符合此约束的 exe 且通过现有 isolation/login/profile 检查，才可报告 available；否则保留具体 reason。QA02 继续记录实际客户端安装形态的缺口。

## 根执行前的无归属窗口消除

helper 创建 unnamed Job，立即设置 KILL_ON_JOB_CLOSE；私有 Job HANDLE 自创建起为非 inheritable，仅 helper 持有，独立于 stdio 的继承设置。用 STARTUPINFOEXW 的 PROC_THREAD_ATTRIBUTE_JOB_LIST，在 CreateProcessW 创建根时同时归属 Job；HANDLE_LIST 只允许目标 stdin/stdout/stderr 的三个显式 duplicated inheritable HANDLE。三个 duplicate 都须有效、非 NULL/INVALID_HANDLE_VALUE、不是 pseudo HANDLE；`CreateProcessW(..., bInheritHandles=TRUE, ...)`，`StartupInfo.dwFlags |= STARTF_USESTDHANDLES`，`hStdInput/hStdOutput/hStdError` 分别指向同一 HANDLE_LIST 中对应三份 duplicate。控制管道、Job、父监视器、测试观察 HANDLE 明确清除 HANDLE_FLAG_INHERIT，且不入 HANDLE_LIST；bInheritHandles=TRUE 不改变这些独立约束。准备参数或创建失败时释放本 helper 所有原始/duplicate stdio HANDLE；成功继承后立即释放 helper 自己的副本，目标继承副本随其所属进程清理。[STARTUPINFOW 标准句柄要求](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow)

CreateProcessW 使用 `CREATE_SUSPENDED | EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT | CREATE_NO_WINDOW`、显式 lpApplicationName 和 cwd。先检查 IsProcessInJob(root, ownedJob) 为 true，再 ResumeThread；失败时根不得执行，终止/释放只属于本次的 HANDLE。不能退回“创建 suspended 根，再单独 AssignProcessToJobObject”：helper 在两步之间崩溃会留下尚未归属的 suspended 根。JOB_LIST 平台下限和 HANDLE_LIST 继承约束来自 [UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)。

helper 可以处于 CI 的外层 Job，payload 放入其嵌套 Job；实际 native CI 必须证明兼容。任一 Job 配置/创建/归属失败，均不恢复目标，不通过 BREAKAWAY 逃出外层 Job。Job HANDLE 与根 HANDLE 生命周期分离：根退出不会释放 Job，后代仍归属；helper 异常退出时，最后 Job HANDLE 关闭触发所属清理。目标后代可自行建嵌套 Job，但所属清理仍必须覆盖它们。

## Node/helper 控制与 literal argv

Node 先建立本轮随机 Windows named pipe `\\.\pipe\atlas-agent-job-<128-bit random>`，单连接，另有 256-bit nonce；helper 启动 argv 只含固定协议选项、pipe 与 nonce。Node/helper stdio 直接用于 payload 的 prompt/stdout/stderr，不混入控制记录。named pipe 作为同用户本轮 capability，不宣称额外权限隔离；nonce、环境、完整命令和 CLI stderr 不写日志/HTTP。

控制帧为 little-endian u32 length + u8 message type + bounded payload。type 固定：HELLO、LAUNCH、READY、ROOT_EXIT、STOP、JOB_EMPTY、ERROR；总帧 ≤1 MiB，状态帧 ≤256 bytes。HELLO 仅 version+nonce；验证后 Node 发 LAUNCH，其字段按顺序为 UTF8 length-prefixed command/cwd、u32 argc+args、u32 envc+key/value。最多 256 args、512 env pairs；strict UTF8/UTF16，无 NUL，env key 禁止 `=`/空串，大小写不敏感 duplicate 拒绝，undefined 环境项不编码；Win32 命令行含结尾 NUL ≤32767 UTF16 code units。帧可连续或任意chunk分割；非法状态次序/重复 launch/未知 type/帧内尾部 bytes/异常长度立即拒绝并清理，重复STOP合法且幂等。

helper 为每个 argv 单独实现 CRT inverse quoting，不经 cmd.exe；空串、空格、双引号、反斜杠尾部、Unicode 在真实 Windows fixture 中往返验证。command 与 cwd 保留 literal 值，目标自身 args parser 的其它语法不由 helper 重写。[CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)、[CRT 参数规则](https://learn.microsoft.com/en-us/cpp/c-language/parsing-c-command-line-arguments?view=msvc-170)

helper 控制 I/O 使用 overlapped HANDLE/event 与有期限的等待，不在同步 ReadFile/WriteFile 上阻塞根退出处理。收到 STOP、owner pipe EOF、根 HANDLE signaled、deadline 或协议失败，进入唯一 idempotent stop。STOP 若发生在 LAUNCH/READY 前，取消创建或不恢复目标。READY 只在已归属且成功 ResumeThread 后发送；ROOT_EXIT 独立于 stdio EOF，禁止等 stdout close 才触发清理。helper 不读取/转发 payload stdio 内容；CreateProcess成功继承后立即释放helper自身的原始及duplicated stdio HANDLE，仅payload保留所需副本，避免helper自身延迟EOF。根/Job/控制HANDLE则持续所属到清理。

## 清理状态、预算与错误

使用 TerminateJobObject 终止整个本轮 Job；Windows 不伪装 SIGTERM grace 或交互 Ctrl+Break。`graceMs` 仍只属于现 POSIX adapter。JOB_EMPTY 依据 QueryInformationJobObject 的 ActiveProcesses==0；不能用根 exit、Job HANDLE 等待或单个 completion-port 通知代替。Windows 终止为硬终止，应用不能推迟。[TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject)、[Job accounting ActiveProcesses](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)

生产预算固定：helper setup/READY 5000ms；运行默认 timeoutMs 120000ms；probe 执行 5000ms/合计输出 65536 bytes；Job empty 等待 2000ms（poll 间隔最多 20ms）；其后 stdio drain 1000ms；gateway drain 5000ms。停止与 setup 共用停止 latch，cancel/server close 不额外等待剩余 setup/execute 期限。终止、helper fallback 和 drain 共用 5000ms 的 process stop 总期限；gateway 随 stop 同步关闭 ingress，整轮 cancel/server生命周期close 的响应总期限 10000ms，覆盖所有 runs、prestart/inspect/probes，不按四个运行或串行 probe 数累加。计时使用 monotonic clock，关闭总 deadline 从首次 beginClose 开始，重复 stop/close 不重置。

正常结束也清理后代：ROOT_EXIT 后 TerminateJobObject→JOB_EMPTY→stdio EOF/受限 drain→done。已有 combined 1 MiB JSONL output budget、unsafe tool/privacy 检查保留。JOB_EMPTY 已证明后，stdio 仍未 EOF 是 AGENT_CLEANUP_FAILED，不返回 ok。

helper ERROR/提前退出/control EOF/STOP timeout：Node 只用自己 spawn 的 helper handle 终止 helper，依靠独占 Job HANDLE 关闭，不凭历史 PID 扫描后代。有限 drain 后返回 AGENT_CLEANUP_FAILED；缺 JOB_EMPTY acknowledgement 就明确“清理未证实”，不能声称已完成所属清理。该 native runner 在当前 server 生命周期内转 unavailable，并使 cached inspect 失效；保留临时 cwd 到已证实 Job empty，未证实时保留有界错误 receipt 路径，不把它作 source/repo 文件。正常 cancellation 只有 Job empty 与 gateway journal settled 才标 cancelled；cleanup failure 的 status 为 failed，即使用户曾点停止。

私有 transport 接口：`launchOwnedProcess(input:{command,args,cwd,env}, scope:OwnedScope): OwnedProcess`，scope 在任何异步验真/启动之前登记且包含 sticky AbortSignal；含 stdin/stdout/stderr、`rootExit:Promise<number|null>`、`done:Promise<{cleanup:"verified"|"unverified";code:number|null}>`、`stop():Promise<void>`。Windows stop/done 总期限按上表；helper故障未观测根退出时rootExit以null结束，不能留下parser等待永不settle的promise，null不代表根已证实退出。`RunningAgent` 和 ChatRun DTO 不增加字段；现JSONL绑定抽为package内部 `bindAgentTransport(input,emit,transport):RunningAgent`，保留解析规则，阶段A的可信test runner可直接使用它与真实Windowsadapter及自己的ownerregistry，不绕过publicguard。阶段B startProcess才条件式选择transport，内部兼容签名 `startProcess(input,emit,ownedScope?:OwnedScope)`：native.start必须传共享registry的scope；既有两参数独立调用由函数建立仅本次所属的scope，调用者仍通过stop/done负责收口。第三参数不放进ProcessInvocation/HTTP DTO。raw probe使用同一 owned transport，不经过 JSONL parser。未关闭时单probe最多 setup5s+execute5s+stop5s=15s，多probe正常inspect串行有界，但一旦close则中断当前phase、禁止后续probe，所有停止并行共用server10s deadline，不能等待原串行检查跑完。

## 注册运行前的 inspect/probe 所属生命周期（I1）

native runner 创建一份内部 `OwnedRegistry`，在 bridge、native status/inspect/start 和 transport 之间共享。可信 `AgentRunner` construction 可以带可选 `ownedLifecycle:OwnedRunnerLifecycle`；没有OS进程的runner由bridge建立内部registry适配。它包含 `registry`、同步 `beginClose()`、`close(deadline):Promise<AgentCloseReport>` 和 `whenIdle():Promise<void>`，均不属于 AgentStatus/ChatRun/RunningAgent HTTP DTO。DTO只显式序列化既有字段，不能把registry、AbortSignal、HANDLE、command/env或完整profile/config对象泄漏到客户端。

registry在每次chat.start进入status await之前登记prestart operation；status endpoint也在进入runner.status前纳入owner范围。首次inspect在创建cached promise前登记实际inspect operation，多个status/chat请求共享同一inspection的owner与abort信号，不为每个waiter重启probe。每个probe在任何manifest检查/异步I/O/pipe listen/spawn前 reserve launch lease。reservation、closing检查与stickyabort绑定必须同步；任何await之后、每个下一串行probe之前、每次spawn/Resume之前都再次检查同一scope。若lease在分配helper前被close，之后不得创建helper；若已分配，则registry已经能用实际owned handle停止。await config/profile/login返回也检查scope，不因close失败重试/退回默认provider/API/auth配置。

bridge/server `beginClose()` 首先同步设置同一closing latch并abort所有prestarts、status/inspect与launch leases，再并行stop已存在的helper和runs，立即关闭已有gateway ingress。cache pending inspection因abort不继续features/login等后续步骤；即使底层filesystem promise不能物理取消，scope禁止其完成后再spawn，将raw work保留在registry追踪，外层HTTP等待abort可有界结束但不冒称底层idle。closing之后新status不启动probe，返回安全unavailable/503；新chat.start以及已在status await的prestart恢复后再次检查closing，拒绝登记StoredRun/启动gateway/CLI，并仅清自身session reservation。已有cached成功status也不得越过closing允许新start。

`whenIdle` 覆盖prestart、所有status/inspect owner（包括cached共享work）、所有launch leases、已登记runs以及已dispatch gateway tasks。只在全部实际settled且所属清理verified时resolve；abort外层waiter或Promise.race返回不等于从registry删除raw work。缺JOB_EMPTY等unverified lease进入quarantine，runner unavailable、whenIdle仍pending，不能当成run已清空就关闭storage。close10s到期返回 `{settled:false,whenSettled}` 与safe pending诊断，registry保留所属；不等待单probe15s或所有串行probe累计期限。正常probe abort验证清理后prestart/status安全失败并释放其reservation；mutation pending沿既有journal规则。bridge registry的prestart计入原四run并发边界，不允许未登记runs绕过上限。

server的生命周期callback在请求可用前注册，main shutdown的whenIdle来自该完整owner，而非遍历runs的snapshot。root HTTP listener可以有界关闭，storage保持到whenIdle；unverified或原work不settle时明确报告关闭未完成，保留storage与一次finalizer，禁止后续spawn/串行probe/Chat start。status abort的reason只描述关闭/机制问题，保留已确定的provider/profile/model/authentication元数据，不将unavailable误写成未登录、错误root/source配置或新的认证事实。

## Gateway 与已派发写入

gateway 关闭必须同步停止新 ingress、关闭本轮 listener 与 owned sockets，不能把 HTTP requestTimeout 当服务执行 deadline。`close():Promise<GatewayCloseResult>` idempotent，其中 `GatewayCloseResult={settled:true}|{settled:false;whenSettled:Promise<void>}`。drain 等待实际 inFlight tasks+network close 5000ms；whenSettled 仍跟踪原 tasks，不复制 mutation、不取消或遗忘已 dispatch 的 app.inject。失败服务响应也算 settled；成功 mutation 在发送响应前写 journal 的既有顺序保持。

超过 5s，gateway listener/sockets 必须已关闭，bridge 的 run 保持 running，errors 增加 AGENT_CLEANUP_PENDING（“本轮连接已关闭，已派发变更仍在收口”），mayHaveSavedChanges=true，changedPlanIds 仅已证实本项目 journal IDs。cancel 在总期限内返回该 snapshot；不释放 conversation active，不允许同一会话启动新 run，不标 cancelled/completed，不声称 journal 全量已确定。后续 poll 继续，whenSettled 后以 failed/AGENT_GATEWAY_DRAIN_TIMEOUT 终结，补实际 journal IDs。无 mutation 的纯读请求也使用该保守路径；历史 snapshot 不伪造为未写入。

`AgentBridge.close():Promise<AgentCloseReport>` 先beginClose完整ownerregistry，再以全部prestart/status/inspect/probes和active runs并行收口，返回 `{settled:boolean;whenSettled:Promise<void>}`；不再接受运行。routes preClose 等待server共用10s deadline内的report后允许Fastify主listener关闭，status/prestart外层等待也须在此期限内abort结束，不留下Fastify等待完整15s/串行inspect。`registerAgentRoutes` 返回完整内部生命周期 `whenIdle():Promise<void>`；`createServer` 新增可选可信 construction callback `onAgentLifecycle` 传给 server main，不增加 HTTP 入口。main index.shutdown 在 app.close 后只在生命周期 whenIdle 确认所有实际work settled及owned清理verified时关闭storage；pending/unverified时有界返回并报告收口未完成，持有storage、附一次whenIdle finalizer，绝不finally提前close DB。错误finalizer只报告安全错误并保留失败状态，无process.exit强退、全机kill或第二个写队列。

持续 pending 的 run 保留原四 active-run 上限，不被 TTL/200 finished cap 错误回收；保护数量有界。没有平台机制能承诺任意不可取消 service handler 的业务终结期限，文档与 UI 必须显示该限制；AG03 的正常 root-first/MCP 生命周期 gate 必须在期限内 settled，永不 settle 的 negative case 只证明有界失败和不假报完成。

## 验收与 guard 的两阶段闸门

阶段 A：当前 guard 保留；实现内部 transport/helper 和测试注入能力，Windows CI 编译本仓库 helper，直接测试 adapter，不通过 public native availability 绕过 guard。阶段 B：主控在独立实现 review 与阶段 A native receipts 通过后，授予条件式 guard 接入窗口；替换为严格 runtime capability refusal，再在同冻结 source/binary 上重跑实际 Windows 生命周期/HTTP gates。缺 helper/不支持架构/shim/manifest失败继续 unavailable；不得凭 Linux SDK 成功直接删 guard。

## 自审和交付边界

自审结果：root-first 与 stdio close 分离；Job 创建归属无 Assign 后补窗口；bInheritHandles/STARTF_USESTDHANDLES/三std HANDLE与私有句柄noninherit分开明确；Node owner EOF 不被目标继承；prestart/status/cached inspect/probe先登记owner、close stickyabort禁止后续串行probe并共用10s deadline；whenIdle不靠runs列表或外层abort假定rawwork清空；硬终止无 grace 伪语义；unverified cleanup/quarantine不伪报成功；gateway ingress与派发写入分别有界/明确pending；storage finalizer不抢跑；platform/shim/binary identity/QA02缺口均可见。I1/M1在plan有对应RED与真实Windows gates；其余通过范围保持。
