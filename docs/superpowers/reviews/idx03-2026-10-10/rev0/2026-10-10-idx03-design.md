## 目标与明确约束

明确捕获 tsconfig references 图、环/越界/缺配置/不可用配置及源码 scope；checker 只读捕获输入；HTTP/MCP/UI 的图事实、诊断与调用源码证据一致。保留IDX02393测试和完整Express35/35入口、SEC lock、旧快照/审批。无目标执行、tsc -b/emit、安装、运行时loader、dist→src推断或IDX04身份迁移。配置图只管理编译配置归属与引用授权，不创造函数/文件调用事实。

官方 TypeScript references path 可指向包含 tsconfig.json 的目录或任意命名配置文件；references 与 extends 不同，引用不继承依赖项目 compilerOptions。通常编译依赖使用输出 .d.ts，编辑器可做源码redirect；本票做捕获源码只读分析，不能把输出路径或类型声明冒充实现。出处：https://www.typescriptlang.org/docs/handbook/project-references.html 与 https://www.typescriptlang.org/tsconfig/disableSourceOfProjectReferenceRedirect.html 。

## 方案比较与选择

A. 自动使用宿主 TypeScript solution builder/输出 .d.ts：拒绝。会引入构建、额外输入和dist猜测。
B. references 仅作为诊断字符串：拒绝。无法检查明确项目图与scope，且不能支持 solution tsconfig 指向 named config 的归属。
C. captured-only 配置图 + 独立归属/引用授权 + 捕获内checker：选定。原始捕获、内部完整有界图、公开有界视图分开，来源清晰；无共享磁盘/安装/emit。

## 捕获与图结构

复用 Configuration category 的512 files/256KiB single/4MiB total。references 顶层必须 array；每项必须 object、path非空静态string。path是文件系统相对路径，允许不带 ./ 的普通相对目录及 Windows反斜线规范化；禁止绝对/drive/URL/仓库逃逸。目录目标仅补 /tsconfig.json，显式 .json 目标保持文件名；不猜其他后缀、不做 package lookup。只通过扫描已许可 .json集合和同一个MetadataReader读取。extends仍按原规则捕获。引用配置的 extends 也需捕获；extends base 的 references不继承为子配置边。

每条边记录 sourceConfigPath、原始引用path、规范化targetConfigPath（越界则没有授权target）、status及reason。有效目标同样由JSONC及extends验证，引用的implementation项目按其有效 composite/files/include/exclude范围管理，空 solution root允许。环、missing、ignored/excluded/symlink/unreadable/budget、非法JSONC/extends/refs形状均明确标记；不能默默漏边或回退另一个近似配置。内部图总预算512配置、2048引用边、16引用深度；共享DAG缓存以path/depth计，cycle检测先于memo；超限scope unknown并诊断。计数只能记录已观察项目/边，不能宣称未读取依赖的完整总量。

一个无效边不使无关独立配置项目失效；对依赖该边的配置closure保守失效。环内及依赖该环的closure不能提供确定归属/跨项目授权。合法独立分支仍有自己的有效scope。不得依据重复拓扑遍历顺序挑选归属。

## Scope与checker契约

- 最近 conventional tsconfig.json（含不可用边界）仍是源码归属的anchor。仅显式可达、有效references可授权任意命名配置；独立named config不可猜测所有者。
- source只属于其anchor的有效候选配置的实际 files/include/exclude/allowJs集合；唯一候选才resolved。0候选unconfigured；多个候选ambiguous；无效anchor/依赖closure invalid。最近无效/排除配置不能回退祖先。
- 引用不传播 compilerOptions；每个源码按所属配置自己的解析选项解析。paths仍优先于IDX02 workspace映射，失败不fallback。
- 显式引用授权与源码导入事实分开。引用图不会自行创建calls/imports，也不把dist/.d.ts输出映射src。有效import必须仍指向已捕获实现，checker唯一声明才建立call。
- refs启用的编译项目采用捕获内scope checker，防止无关项目global script同名实现串边。优先按配置scope建立in-memory Program/Project，只纳入owned sources与已授权引用closure；依赖源码可用于checker，不重复抽取函数节点。跨Program声明用捕获文件/语法位置内部key连接现有Graph ID；不迁移外部节点身份。绝不可用文本名跨项目查找声明。
- 没有refs的既有合法解析行为保持；新graph不得让IDX02已授权workspace导入或既有相对导入无故失效。有refs配置的跨项目策略在实施前需主控确认：建议引用closure约束编译项目全局作用域，而真实字面量import仍可在已捕获授权范围内连接物理模块，禁止通过无import的global符号借另一个项目。若TypeScript公共API/模型不能证明，unknown并明确限制，不假称完整solution builder。
- native ts.createProgram允许 projectReferences；ts-morph ProjectOptions不提供该字段。实施需在captured in-memory边界内选择scope Project或native checker adapter，不把真实目标文件系统交给compiler。实际选型必须由最小RED行为及独立设计复核确认。

## 公共API需求（主控已认可方向，窄字段own待协调）

建议 CodeSnapshot.coverage 可选 configurationProjectGraph，legacy absent代表未记录，不能当零：
- version:1；status complete/partial（graph inspection已观察范围，不能作为compiler valid替代）。
- counts: observedProjects、observedReferences、sourceScopes 与 resolved/unconfigured/ambiguous/invalid各scope count；observed计数不声称未知依赖总量。
- roots（有界数组）；projects {configPath,status}；references {sourceConfigPath,referencePathPreview,targetConfigPath?,status,reason?,referencePathTruncated}；scopes {sourcePath,configPath?,status}。
- truncated:{roots,projects,references,scopes}逐集合明确。公开默认≤50roots/50projects/100edges/50scope样本，按repo路径稳定排序。计数在slice之前计算；未列出scope只表示未返回，绝不能视作unknown或全部已覆盖。公开path字段≤2048字符，过长行从样本省略并标truncated；引用path预览≤256、reason≤512并显式preview截断。内部原始配置bytes完整保留捕获/hash，内部scope查找不依赖公开样本。
- graph budget失效status partial并诊断，sample truncation仅代表传输截断，不取消内部有效授权。声明图完整时所有已观察counts与returnedCount/truncated一致。

core model.ts/validation.ts/export测试需窄字段改动；服务无需新port、存储SQLite JSON无需迁移；HTTP/MCP get_project_summary现有coverage pass-through，不新增tool或route。严格schema兼容历史无字段。若需要summary再压缩图，必须core queries统一实现，让HTTP=MCP且counts/flags一致，不能只在MCP隐藏graph。
