# POL-01 structure.json Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户可从现有工程面板读取/修改可移植 v1 目录约定，并得到可恢复的 SQLite 同步、明确冲突和真实摘要审计。

**Architecture:** `.codemap/structure.json` 是可移植来源；core 负责完整 JSON/schema/patch，storage 提供文件适配器，service 用项目队列和 SQLite intent journal 编排。文件发布成功后再一次性 finalize 投影和规划失效；启动按实际 disk digest 恢复，不重放第三方已改文件。

**Tech Stack:** 现有 TypeScript 5.9.3、Node 24.19.0/npm 11.9.0、Zod、better-sqlite3、Fastify、React/Zustand、Vitest/Playwright；不新增第三方依赖。

**Spec:** `docs/superpowers/specs/2026-10-10-pol01-design.md`。状态：首次独立审查 C0/I2/M2 已完成；本文针对四项修订，限定复审与产品实施尚未发生。下面 checkboxes 只记录未来实施进度。

## Global Constraints

- POL-01 的依赖 UI-04 已完成。本票只做 v1 读取、schema 校验、规范化、双向写入、来源/摘要审计及同步状态展示。
- POL-02 的 allowed/forbidden 编辑、有理由例外及新的规则执行器仍留在 POL-02；本票保留它们的已有数据，不把保留或 schema 校验称为规则满足。
- 读入上限 1 MiB UTF-8 bytes；无效 UTF-8、非法 JSON、重复对象 key、schemaVersion 非 1、错误字段类型、超过上限均返回带 JSON pointer/错误类的诊断，保留原 bytes。
- 首版不支持两个 server 对同一项目同时写入，不新增跨平台文件锁/租约系统。
- 所有写和 finalize 使用 StoragePort.transaction 的同步边界，await 只发生在事务外。
- source 值只能由 server/use-case 赋为 ui/external/legacy_migration；客户端不能指定 source、verifiedAt、audit 或 projectId。
- 独立任务 GRP-02 正在修改共享 core/service/routes/workspace，实施必须等其 freeze 后顺序集成。
- 只 main 可阶段 commit/push；本设计者不改 global docs、不改 generated memory、不清理复核现场。

## Review Focus

1. 外部合法文件与已有 DB-only policy 重叠：迁移前同id编辑保持DB来源，迁移finalize原子切换、plan+1；Task 3 pin。
2. 重命名 folder 时未知嵌套值及省略 allowed/forbidden：只 patch owned 字段，未知数据不 strip；Task 1 pin。
3. rename 已发布但 fsync/DB reply 失败：返回 recovery_pending，重启只能按实际摘要恢复一次；Tasks 2/3 pin。
4. 用户切项目时旧请求晚到：旧 state/冲突草稿不进入新项目；Task 4 pin。
5. 非法、删除、恢复后格式-only 外部文件：旧 approval 不伪装有效，重复读不重复增版本；Task 3 pin。

## Task 1：可保留信息的 v1 纯模型

**Files:** Create `packages/core/src/structure-types.ts`, `packages/core/src/structure.ts`, `packages/core/src/structure.test.ts`; Modify `packages/core/src/index.ts`。

**Interfaces:**
- `JsonValue`、`StructureDocumentV1`、`StructureFolder`、`StructureDependencyRule` 每层允许 JSON unknown fields；reserved x-atlasmode legacy 扩展显式 typed。`StructureStatus`、`StructureState`、`StructureAudit`、`StructureWriteInput` 按 spec 字段；state.fileDigest/semanticDigest 为 string|null，structureRevision 是非负 integer，verifiedAt 是 UTC ISO string。
- `StructureDiagnostic` 为 `{pointer:string,kind:string,message:string}`；`StructureError extends DomainError` 公开 diagnostics 数组。`parseStructure(text:string): StructureDocumentV1`：纯解析/校验，失败 StructureError `INVALID_STRUCTURE`，diagnostics 含 pointer 和类；检测重复 key。
- `canonicalStructure(document:StructureDocumentV1): string`；只产生摘要输入，不改原 document。
- `applyStructureOperation(document,operation,legacyPolicies:DirectoryPolicy[]): StructureDocumentV1`；不突变输入，importLegacy 检查扩展冲突及所有者由 service 提供的既有本项目 policy 集合。
- `projectStructurePolicies(document,projectId:string): DirectoryPolicy[]`；folder 空禁止前缀与 legacy extension 保持两种语义，id 使用 spec 公式。
- `StructureFilePort.read(rootPath:string): Promise<StructureFileRead>`，read 为 `{bytes:Uint8Array|null,digest:string|null,verifiedAt:string,diagnostics:StructureDiagnostic[]}`。missing 是 bytes/digest 均 null；oversize 可流式求真实digest但不保留全文，bytes=null、digest非null、诊断明确invalid；无效UTF-8同样返回真实digest/diagnostics。这样 invalid 重复读取有稳定观察版本且不会冒充missing。`publish(rootPath:string,input:{mutationId:string,expectedDigest:string|null,bytes:Uint8Array}): Promise<StructurePublishResult>`，result 为 `{phase:"published"|"not_published"|"uncertain",actualDigest:string|null,errorCode?:string}`。实现必须返回发布阶段，不能将 publish 之后错误冒充未写。
