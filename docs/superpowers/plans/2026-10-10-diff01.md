# DIFF-01 Captured Snapshot Diff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans after main grants exact product ownership windows. Steps use checkbox syntax. Current phase is design only: no implementation/tests/build/DB/stage/commit/spawn.

**Goal:** Present complete bounded same-project captured snapshot differences, caller/reference changes and static abstraction-bypass evidence with truthful unknown scope.

**Architecture:** A versioned optional raw-input manifest augments future captures; the IDX04 exact evidence and accepted pair ledger provide readonly correspondence. Pure core comparison runs over a bounded immutable pair; service/HTTP/MCP and an independent UI expose the same paginated result without refresh or knowledge/approval writes.

**Tech Stack:** Existing Node24/npm, TypeScript, Zod, synchronous SQLite StoragePort, captured indexer buffers, React and Playwright; no new package or runtime/extra language capability.

**Spec:** docs/superpowers/specs/2026-10-10-diff01-design.md

## Global Constraints

- Current authorization owns only spec/plan/readonly evidence; main assigns all shared product windows after IDX04/KN/FS/POL interfaces stabilize.
- Only same-project immutable pair; same-ID or accepted exact-pair correspondence; no candidate autoaccept/globalalias/plan rebase/knowledge mutation or verify semantic change.
- Producer/write accepts only valid diffInputManifest v1/sha256-raw-v1/captured-v3; ≤20000 entries/8MiB, path≤2048. Historical `CapturedSnapshotDiffReadModel` uses layered optional-version parsing: absent/unsupported bounded opaque evidence unknown, known malformed INVALID_SNAPSHOT. IDX0420k/16MiB bounds unchanged; raw JSON depth64/token1000000 and duplicate-object-key limits apply before full parsing.
- Per snapshot serialized bytes≤33554432 before fetching/JSON parsing; pair≤64MiB; combined nodes+relations≤50000, mappings≤20000, twohop expansions≤50000, result≤50000 rows/16MiB; excess raises DIFF_BUDGET_EXCEEDED with no partial success.
- Pages default20/max50; offset0..50000; response≤64KiB, row≤8KiB, preview≤256/reason≤512 with truthful truncation; nextOffset uses returnedCount.
- Pair reader and pure compare both validate duplicate IDs/dangling references/resolution consistency before comparison Maps, mapping or reference statistics; validation-only Sets bounded by facts50k and semantic-work200000. Known damaged records never become unknown/last-value-wins or storage repair.
- Same-transaction bounded exact ledger reads: project metadata16KiB, registry1MiB, selected record64KiB, registry+selected aggregate16MiB, acceptedIds/correspondences20000, key batches256. Length-first, cardinality lexical preflight before JSON.parse; absent capability DIFF_UNAVAILABLE, no generic get/list fallback.
- comparisonComplete describes captured-set calculation, captureState describes supported analysis scope; observed counts never imply runtime completeness/dead code.
- No source execution/import/write/move, snapshot writes, refresh/reconcile, DB migration, new dependencies, approval/context/history changes. Main handles commits/rootclean gates and preserves raw failures.

## Review Focus

1. Old ID reuse or same-name copy plus a pending/foreign mapping must not turn a genuinely new fact into old identity (Task2).
2. Parse/metadata/unsupported/excluded gaps or line-generated relation IDs must not fabricate deletion/reference loss (Task2/3).
3. High-degree wrappers, oversize snapshot JSON and Unicode/sourcepaths must be rejected before unbounded materialization (Task1/2/3/4).
4. A→B→A, current pointer/ledger change and stale pagination must not display evidence for the wrong project/pair (Task4/5).
5. External package-name targets and planned ownership/GRP mirrors must not become runtime proof or duplicate callers (Task3/5/6).
