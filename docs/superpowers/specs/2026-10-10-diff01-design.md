# DIFF-01 完整捕获快照差异与引用变化设计

2026-10-10，设计窗口；明确模型 gpt-6.1-sol high。依据 `docs/tickets/DIFF-01.md`：调用方减少、引用消失、抽象绕过展示证据；零入边不是死代码；unknown/排除范围清晰。本轮只新增本 spec、对应 plan、专属只读依据，不实施产品、不运行测试/build/DB、不改全局文档/票状态、不 stage/commit/spawn。主控另安排独立 high 审查。

## 用户目标与实际缺口

用户刷新索引后，选择同项目两次已保存捕获，查看函数/文件/关系的变化及两侧来源，分清已观察到的引用变化、采集范围变化和无法判定项；能够检查“调用已有 wrapper 改成直接调用其底层目标”的证据，但不能由此推断执行顺序、业务错误或死代码。

实际 `CodeSnapshot` 保存 nodes/relations/diagnostics/coverage、Git revision 和 captured-v3 整体输入 hash。`SourceIndexer` 以捕获 bytes 提取事实，capabilities/diagnostics 参与 facts fingerprint；历史 source bytes 没有持久化。`readSource` 读当前磁盘，不能当历史源码。Graph 的 node ID 含项目/路径/限定名/declarationKind；relation ID 含端点、证据路径、行号和生成序号，空行可改变 relation ID。现 `getFunctionContext` 是当前快照分页直调用视图；现 `verifyPlan` 会刷新索引，比较历史已批准 plan 与当前事实，`VerificationPanel` 显示 satisfied/unmet/unknown。没有完整快照对差异查询或历史源码查看器。DIFF 查询不得调用 verify/refresh 或把其 approval 语义改成迁移 alias。

IDX04 已 APPROVE 的 spec SHA `439750c81287069a7c48b0f61d03f1275fec365780a59a5149389239ed86ba32`；窄修后的 plan SHA `d6f058cad14305ac7b6568c3cba45c08c2ba86fd1e926fa950fa78d813bb6794`。它仍是设计依赖，不假设模块已存在。DIFF 必须在其 public 契约落地且获产品窗口后实施。

## 方案选择与范围

1. 比较当前分页 subgraph 或 readSource/live Git 重建过去：拒绝。分页遗漏不是删除，当前 bytes 不是历史证据。
2. 自动按名字/摘要/调用邻居匹配两个图并 rebase 知识/规划：拒绝。绕过 IDX04 显式接受与 immutable approval 边界。
3. 同项目 immutable snapshot pair，完整有界比较；严格 same-ID 或已接受同 pair 对应；输出捕获来源与 unknown：采用。查询与 UI 都只读，输出是静态事实变化报告。

本票不加运行时追踪、额外语言解析、源码备份、通用语义 diff、批量重绑/rebase、代码执行/移动/写入、自动修复或批准。完整快照指两侧完整的**已捕获事实集合**，不等于整个磁盘/所有语言/完整运行时真相。超过硬预算早拒绝，不抽样报告为完整。

## IDX04 接口边界与最小新捕获数据

依赖 IDX04 public types `IdentityFactRef`、`IdentityEvidenceEntry/Capture` 和已接受映射 read model。DIFF 只消费以下数据，不调用 candidates/accept/bindMany：

- optional `CodeSnapshot.identityEvidence`，已批准 exact digest/version/language/shape/preview/previewTruncated/capture counts。原 digest 正规化只证明该规则定义的捕获内容相等，不能证明行为等价；函数 whitespace/comment-only 变化不宣称实现改变，文件 raw digest 仍可显示输入字节改变。
- 同项目、精确 `{fromSnapshotId,toSnapshotId,fromHash,toHash}` registry revision 与不可变 accepted records。由 IDX owner提供 core public `AcceptedIdentityCorrespondence = {recordId,from:IdentityFactRef,to:IdentityFactRef}` 的只读投影和严格解析函数 `readAcceptedIdentityCorrespondences(projectId,pair,expectedMappingRevision,boundedReadPort): AcceptedIdentityCorrespondence[]`，与 snapshot reader 共用同一同步 readonly transaction；原始读取硬界限见下文，不能仅在返回数组后限数。此名为待协调新增公共投影，不能从 web/service 深层导入 IDX 实现。必须验证 version、actor=user、pair/hash、one-to-one、事实存在/kind、记录引用一致性；损坏记录 failclosed `INVALID_MAPPING_LEDGER`，不静默退成空映射。关系映射只接受其被记录的 exact pair，不从 node 映射推导 relation identity。
- 相同 domain ID 优先为同一事实；accepted mapping 只用于两侧都存在的精确旧→新 ID 且不能撞 same-ID 对应。只限该 pair，不跨快照链/global alias、不采纳 unique/ambiguous 候选未接受结果。历史 pair 可读其曾接受的记录，即使 to 现在不是 current；它仍只是当时用户声明的延续。

现有整体 contentHash 无法分辨某一个 config/package 是否变化。新增最小 optional `CodeSnapshot.diffInputManifest`，由 DIFF 的独立 capture hook 在 scanner **已有** source/configuration/package buffers 上构造，不重新读取目标：

`{version:1,hashAlgorithm:"sha256-raw-v1",inputHashVersion:"captured-v3",supportedLanguages:["typescript","javascript","python"],entries:[{kind:"source"|"configuration"|"package",path,sha256}],observedInputs,recordedInputs,truncated}`。

source entry 包括现有支持源码 raw bytes，配置/package 包括已捕获元数据 bytes；key=(kind,path)，排序去重，SHA256小写64hex，规范完整相对路径≤2048字符，非负计数与记录长度一致。最多20000 entries、完整 JSON UTF-8≤8MiB；稳定截断并记录 observed/recorded/truncated，遗漏项只能 unknown，不影响原提取 calls/IDs。supportedLanguages 是当前适配器支持范围声明，不宣称所有不支持文件均被枚举。manifest 参与新 facts fingerprint，保留 captured-v3 contentHash/makeId 原规则；旧 snapshot 不回填/不默迁移，manifest missing/未知版本是 input-evidence unknown。IDX04 evidence 所有预算保持，不能扩大其20k/16MiB。

这个新增字段仅为精确输入/配置变化的必要接点，需主控授 core/model/validation/index、indexer scan/index 小窗口，先与 IDX owner 约定最终 public 类型。新模块 schema 仅用 Zod/model type，不反向运行时导入 validation，避免循环。不需要新 SQL table/migration/RecordKind；快照仍 immutable JSON。无法获得该字段窗口时不能宣称精确配置内容差异，只能保留 unknown，票不 DONE。

**I2 分层版本合同：** capture producer/public write schema只接受合法v1 manifest，拒绝其它版本或malformed。DIFF历史读取使用专属 `CapturedSnapshotDiffReadModel` 与 `parseCapturedSnapshotForDiff`，不能直接让当前literal-v1 optional schema拒绝整个历史snapshot，也不能把任意schema错误降级。先执行raw字节/JSON深度64/总token1000000硬预算与重复JSON对象key拒绝；strict校验base snapshot已知字段、project/id/事实，再独立识别两个optional evidence字段。字段不存在是legacy missing；字段是有界对象且有合法正整数但不支持的version时，保留 `unsupported` 状态，payload opaque且不进入正文/配置/身份比较或摘要输出。input manifest opaque字段仍≤8MiB，identity evidence opaque字段仍≤16MiB，并包含在32MiB整row预算；未知版本不能绕过预算。version缺失/非整数/非正数、非对象、已知v1重复typed key、坏digest/count/path/引用或base已知字段损坏均是 `INVALID_SNAPSHOT`，不降级unknown。合法未知版本的base metadata仍可比较，input/body相应unknown；不从当前source/其它快照补证据，不回写。identityEvidence分层parser必须由IDX owner提供最终公共合同后复用；未提供则依赖阻塞，不猜内部格式。此read model不改变全局旧snapshot schema/写入语义。

read model保留base已知字段和每个evidence `{state:"missing"|"supported"|"unsupported",version?,validatedValue?}`；validatedValue仅supported存在，unsupported原payload经过有界preflight后丢弃而不复制给pure compare/UI。direct pure入口同样检查state/version/value一致性及base/已知value预算、语义；不能让手工构造read model跳过验证。未知版本未定义的内容不被当作已知事实/evidence；已知base extra fields仍按既有strict合同拒绝。

## 输入、读取与预算

公开 `SnapshotDiffInput` strict schema：`{fromSnapshotId,toSnapshotId,fromContentHash,toContentHash,expectedMappingRevision,scope:"current"|"historical",expectedCurrentSnapshotId?,section:"facts"|"relations"|"references"|"bypasses"|"coverage",offset?,limit?}`。projectId 由 route/MCP project scope 决定。from≠to；两个 IDs必须属于该项目已存快照；caller 不能提交 snapshot/evidence/mapping/actor 或 arbitrary filters。current 模式要求 expectedCurrentSnapshotId==to 并在读事务内等于项目指针；historical 模式禁止该字段。两侧 hashes/registry revision 均需匹配，409保留用户选择并要求重新读取。排序稳定，不按浏览器 arrival 顺序翻页。

`getSnapshotDiff(projectId,input): SnapshotDiffPage` 在单个同步 readonly storage transaction 内读项目指针、pair、ledger；不 await、不刷新索引/结构、不 reconcile、不写任何 settings/knowledge/history/approval。对不同项目 ID 不返回其 metadata/证据。不存在或 foreign snapshot 返回 NOT_FOUND；tuple/hash/current变化为 SNAPSHOT_CHANGED；ledger CAS为 REVISION_CONFLICT；非法schema为 INVALID_INPUT。

新增窄 `SnapshotDiffReadPort.readSnapshotPair(projectId,{fromSnapshotId,toSnapshotId,maxBytesPerSnapshot:33554432}): {from:CapturedSnapshotDiffReadModel,to:CapturedSnapshotDiffReadModel}`，由同一storage实例在该事务执行。SQLite先 `length(CAST(value AS BLOB))` 检查两个指定row的serialized bytes，任一>32MiB在取value/JSON.parse前拒绝；随后单条带长度谓词read取值，执行分层parser与下述bounded语义验证。不得使用StoragePort.list("snapshots")或两个无界get后stringify当早期拒绝。若其它adapter没有此有界能力，返回DIFF_UNAVAILABLE，禁止fallback。本设计不改变泛型get/list既有语义，也不加索引或迁移以规避KN严格schema合同。

**I1 比较前结构验证：** pair reader和pure compare入口均执行 `validateCapturedSnapshotForDiff`，不信任调用方曾用strictObject解析。先检查合计nodes+relations≤50000，再以validation-only有界Sets证明每侧node ID唯一、relation ID唯一（完全相同payload重复也拒绝）；sourceId必须存在，非null targetId必须存在；resolved必须非null且目标非external，external必须非null且目标kind=external，unresolved必须targetId=null；parentId存在时必须指向同侧真实node。已知identityEvidence fact引用存在且kind匹配、fact key唯一；manifest `(kind,path)` 唯一，不把configuration/package entry假作node。unsupported opaque不进入算法。结构验证工作≤200000次（逐事实/parent/endpoint/已知evidence/manifest项计数，在下一项前检查）；超限为预算错误，损坏为稳定 `INVALID_SNAPSHOT`。成功前不得构建比较Map、映射/调用统计/bypass索引；禁止last-value-wins、去重修复或回写。合法unresolved-null与legacy optional evidence缺失仍通过；不重推历史Graph hash ID或重新解析源码。

**I3 原始ledger有界接口：** IDX projection使用同一storage的 `DiffBoundedRecordReadPort`：`measureExact(kind,ids,{maxKeys}): {id,byteLength|null}[]` 仅返回exact-key长度；`readExactWithin(kind,measured,{maxEachBytes,maxTotalBytes}): {id,rawUtf8}[]` 再用长度谓词取指定值；每批最多256 keys。project/pointer exact project row≤16384 bytes；registry exact key为IDX合同 `identity-mapping-registry:<project>:<fromSID>:<toSID>`，≤1048576 bytes；每个 `identity-mapping:<acceptedUUID>` row≤65536 bytes；registry+全部selected records合计≤16777216 bytes；acceptedIds与最终correspondences各≤20000。limits是server常数，不接收caller放宽。

先length检查project/registry，再取bounded raw；JSON.parse前bounded lexical/structural preflight（深度64、token工作按raw bytes有界、重复对象key拒绝）检查registry顶层acceptedIds cardinality，在第20001项前拒绝；随后strictparse验证version/revision、UUID项唯一与无extra fields。拿到有界确定IDs后，仅分批measure这些selected exact keys，在任何accepted value物化/parse前检查单项和全部合计length/maxkeys；通过后分批取值/preflight/strictparse，验证record ID、actor=user、exactpair/hash、registry引用/one-to-one和已验证事实存在。registry原始1MiB门在这些工作之前。missing/foreign/other-pair/duplicate/已知malformed ledger=`INVALID_MAPPING_LEDGER`；raw/count/aggregate超限=`DIFF_BUDGET_EXCEEDED`，无partial/空映射fallback。exact registry不存在仅在bounded能力证明absent且expectedMappingRevision=0时表示合法空ledger，其它revision仍冲突。缺任何bounded能力或不能共享transaction=`DIFF_UNAVAILABLE`。禁止generic get后stringify、list全settings、候选链/其它pair扫描；巨大unrelated settings不参与。此为最小storage/IDX只读接点，不更改通用get/list或IDX接受/写入语义。

ledger preflight总token≤1000000（registry+selected累加，下一token前检查），扫描字节工作≤两倍已量测aggregate bytes；不是20000个record各自重新获得无限工作预算。pointer metadata及registry/record的已知schema对象keys必须strict，所有错误保留原始row且无部分成功。

**M1 Task1前置门：** 基线选择复用IDX04 `listIdentityBaselines(projectId,{offset,limit})`，实施前IDX/Storage owner必须提供 `IdentityBaselineMetadataReadPort.readPage(projectId,{offset,limit}): IdentityBaselinePage` 与测试，不在UI阶段临时generic list后slice。Page字段：projectId/currentSnapshotId、metadataRevision、items `{snapshotId,contentHash,createdAt,gitRevision}`、offset/limit/returnedCount/nextOffset/hasMore、indexedTotal、`total:number|null`、`totalState:"exact"|"unknown"`、`coverage:"all-captured"|"indexed-subset"`。默认20/最多50，offset≤20000、project metadata rows≤20000、每row≤8KiB、project aggregate≤16MiB、response≤64KiB；nextOffset按returnedCount，分页不把样本当total。adapter只读project-scoped metadata header（IDX未来capture可在现settings内原子保存derived header/coverage marker，无新SQL migration），count/length/aggregate先于raw读取/parse；不读取snapshot完整JSON、不扫描/物化其它项目或巨大unrelated snapshot。exact total仅在同事务证明coverage=all-captured及header计数一致时给出；legacy无header不默回填，indexed-subset显式total=null/unknown，仅展示已有可验证header。缺能力/coverage marker不可信时selector显示DIFF_UNAVAILABLE、不可选，不返回空列表冒充无历史。此待协调能力不是已有实现，DIFF不另造history平台、不调用to-current candidates接口；pair query仍按两个指定SID只读。IDX/Storage owner公共schema、sameTXN能力/metadata生成责任和前置门证据未明确前，Task1产品窗口不得开始。

metadata接点提议exact settings keys为 `identity-baseline-registry:<project>` marker（version/revision/projectId/coverage，≤16KiB）和 `identity-baseline:<project>:<SID>` header（version/projectId及上述四metadata字段，≤8KiB）。owner必须在Task0冻结最终keys/strict schemas；SQLite仅以canonical project key范围取count/sum(length)及有序page的有界headers，转义SQL通配符并验证header.projectId/SID与key匹配，不用snapshot JSON_EXTRACT扫描重建metadata。marker/headers同storage事务读取、按createdAt+SID固定排序，marker缺失/坏schema/未知version不造exact total；partial marker可返回unknown。metadata lexical深度64/token1000000/aggregate16MiB也受硬界限，过量为DIFF_BUDGET_EXCEEDED。IDX负责证明all-captured marker来源/原子capture维护，旧无header项目不自动声称complete；未能提供这些具体能力就是前置阻塞，无产品fallback。

硬上限：两个快照合计 serialized bytes≤64MiB；合计 nodes+relations≤50000；accepted correspondences≤20000；两跳 bypass 展开检查≤50000；完整内部结果≤50000 rows且serialized JSON≤16MiB。预先核对 bytes/counts，扫描每个迭代增加工作计数并在生成超限项前停止，不能先构造笛卡尔积再slice。任一硬上限超限返回 `DIFF_BUDGET_EXCEEDED {dimension,limit,observedAtLeast}`，无部分差异页/假 total/“没有变化”。用户可选不同 pair，不能降低输出limit绕过计算预算。该拒绝不影响既有图查询/快照。

每页默认20、最大50，offset安全整数0..50000；整个serialized response≤64KiB。字段preview≤256字符带truncated flag且不割surrogate，路径完整≤2048，reason≤512；单行≤8KiB，不可表示则有界错误。实际返回条数可能小于limit，nextOffset=offset+returnedCount；仅切页造成 pageTruncated/hasMore，不改变完整section total。每次从同 pair+mappingRevision确定性计算，暂不持久化报告或新增后台cache。byte/page预算必须覆盖所有summary/coverage/evidence字段，不返回巨大 manifest/ledger/源码正文。

`comparisonComplete:true` 只表示预算内完成两个捕获集合的比较；独立 `captureState:"complete-supported-scope"|"partial"|"legacy-unknown"`、`identityEvidenceState`、`inputEvidenceState`、`limitations` 说明证明能力。未知采集仍有已观察正例，但不得将 observed counts当全项目运行时 totals。

## 输出分类与来源

Page envelope：version1/projectId、两侧 snapshotId/contentHash/createdAt/gitRevision、scope/currentAtReadSnapshotId、mappingRevision、以上证据状态、section、items、total/offset/limit/returnedCount/nextOffset/hasMore/pageTruncated、bounded summary counts。旧/新 snapshot 与当前指针分别显示；currentAtRead 是读取时状态，不伪称当前磁盘新鲜。UI切换/refresh后清除匹配旧 generation 的 current-mode结果；历史模式保留显式标签。

所有 item 有稳定key、`change:"added"|"removed"|"modified"|"unchanged"|"unknown"`、knownChangedFields、unknownReasons、pair-specific provenance。同ID/accepted identity 对应标 `identityBasis:"same_id"|"accepted_mapping"` 与recordId；未接受异ID各自显示捕获新增/缺失，旁注身份延续未确认，不能称真正新生/消亡。missing capture version只是证据 unknown，不自动成为一条新增/删除。

- facts：function(含method/class的declarationKind)、file、folder、external各自比较。已捕获正例可报告一侧出现。另一侧缺失仅在该事实的支持范围可完整证明（availability.complete、相关path/subtree未excluded/unavailable、相关parser diagnostics未失败且语言支持一致）时叫“从捕获事实中移除”；否则 unknown。这仍不是“实现已死/磁盘已删”。同对应的公开metadata变化为known modified；实现digest只有两个同version/language/shape complete entry可比较。没有digest时保留metadata变化与 implementation=unknown，metadata相同也不能声称正文未变。file raw bytes、normalized implementation、位置/署名/导出变化分别列facet；不把comment-only file字节变化冒称行为改变。
- relations：只same-ID或显式accepted relation mapping认为同relation；逐侧保存type/resolution、真实source/target ID（可null）、两侧 captured file/line/text/reason及截断。没relation mapping的行号/序号变化仍可列捕获关系removed+added，并明确 relation ID由location生成可能变动。reference统计用已对应端点的type/resolution聚合多重集合，故单纯行号变化不会谎报caller减少；这不是隐式relation identity接受。unknown/unresolved/external保留自己的类别、原因与来源；不猜target，不把imports当function calls或把contains当依赖。
- coverage/config：对照支持语言声明、coverage.files、configurationFiles、packageFiles、excludedPatterns/Paths、unavailablePaths、diagnostics、configurationProjectGraph status/scope/reference/truncation字段。manifest使同(kind,path) rawdigest改变可报告配置/元数据输入改变，但不声称该字节导致某条关系。只有整体hash变化没有完整manifest不能归因为config。图配置范围/status变化与字节变化分别列出，父配置/包条件的运行时含义待人判断。范围缩小后旧事实缺失是 unknown。
- 每个证据都带 side/snapshotId/factId/domain endpoints、physical relative path、line(若捕获)、digest类型/版本(若有)、captured preview与truncation；旧preview仅“捕获摘要”，不是完整源码。没有原始截断标记的 legacy signature/relation text 标 inheritedTruncation=unknown；本次传输另有 previewTruncated，不能因为传输没再截断就承诺原捕获全文。live source打开使用现有安全source endpoint，明确“当前磁盘”，不得把当前内容覆写历史证据或源定位。历史事实不能调用只接受当前domain ID的inspect API；用独立readonly证据页。FS planned path/GRP alias/temp节点不进入事实比较；真实domain ID与visual ID不同。

## 调用方减少、引用消失与抽象绕过

调用方是解析后真实function节点的 unique source identity；引用位置是 calls site多重集合，分别显示 before/after observedResolvedCallerCount 与 observedResolvedSiteCount。同caller三个call减少到一个是site减少，caller数量不变；recursive self-call标明且不混成外部caller。imports另展示文件级引用；不从imports/contains生成函数调用。多对多 group镜像不重复计数。

`reference_loss` 行只有目标与caller对应均严格、两侧整个相关静态搜索空间完整且无可能隐藏此目标的 unresolved/未知配置/解析/排除项时才标 `confirmed_static`。否则 `unknown`，仍可显示真实已观察到的边与“observed 3→1”，不称完整引用减少。保守实现：任一侧相关语言/未知语言的采集缺口或unresolved calls使负向引用结论unknown；有界 response包含unknown类别count及分页具体来源，而不是将其target写成目标函数。零已解析入边仅显示“在此捕获范围中未观察到直接调用；外部入口、框架注册与动态调用未被排除”，永不输出 dead/unused/remove建议。

静态 bypass 候选的唯一定义：同pair对应的三个不同真实function A/W/T；基线存在已解析直接 A→W 与 W→T；to中 W仍以same-ID或显式mapping存在；A→W observed已减少/为零；A→T已解析直接site数量较基线增加。新旧真实边各自可查看、source+target+file/line可定位。基线已存在A→T且未增加不报新增绕过；只W→T变化/无A对应/未知目标/无wrapper真实call不报确定候选。两侧负向空间不完整时保留 `unknown_bypass_pattern`，不显示confirmed loss。不得搜索任意深度/运行时顺序，允许有事实但不判需求错误；标题“可能直接绕过已有抽象（静态证据）”。不把一般低层target/同名函数自动指定wrapper。
