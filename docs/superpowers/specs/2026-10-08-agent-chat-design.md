# Local Agent chat and planning shell

User chose local Codex/Claude Agent bridged to web Chat, 2026-10-08. This design covers AG-01, UI-04 and QA-01 after focus/navigation tickets. Standing autonomous authorization applies; do not restart Cloudflare.

## User experience

Left panel is repository exploration chat with contextual navigation/search suggestions; right panel has compact current planning overview, changes and planning chat. Both pass current project, selected scope/function and selected plan to the Agent. They are separate conversations scoped to project. No raw MCP arguments/outputs, schema forms or reasoning trace in ordinary UI. Tool activity appears as concise status and resulting graph changes, with detail in engineering documentation. Source is available via a contextual drawer, breadcrumb or card action. Project selection, theme/language, search/navigation, undo/redo, explicit plan selection, validation/approval/export/verification remain accessible compact actions. Agent never confirms a user's plan. Advanced old forms may be opt-in compatibility drawer until all earlier covered features have accessible replacements; no default technical panel.

## Real bridge

Use local CLI adapters, spawned with argument arrays (no shell). Default Codex supports `codex exec --json --sandbox read-only`, ephemeral runs and process-local MCP configuration that launches the already built AtlasMode stdio MCP with CODEMAP_API_URL pointing at this server. Claude adapter supports its installed documented print/stream JSON mode and process-local MCP config; test protocol normalization independently and mark absent CLI/native login honestly. Use the installed CLI's default model, with optional trusted CODEMAP_AGENT_MODEL override; isolate user tool configuration deliberately and disclose this in setup docs. Existing account authentication remains local. Custom provider configuration is not silently inferred; unsupported provider setup reports unavailable. No hardcoded model or API key. Never edit global Codex/Claude settings, expose credentials or accept browser executable/path/CLI arguments.

Configuration is explicit via server environment: CODEMAP_AGENT_PROVIDER=codex|claude, optional CODEMAP_AGENT_COMMAND trusted administrator executable, no client-supplied process configuration. When unconfigured/unavailable show a clear disconnected message; submitting must produce an honest error, never canned success. Check CLI/login availability separately from SDK tool connectivity. This environment currently has Codex0.160.0 but `codex login status` says Not logged in, and Claude executable is absent. Real model completion cannot be claimed without later successful authenticated execution.

Backend Chat bridge is an I/O adapter in apps/server, consumes service data through public APIs and local HTTP/MCP subprocess, not separate SQL or domain rules. Bounded in-memory session history/runs (20 turns per project/channel, 4096-character messages, 65536-character retained history, 1MiB output/run, 10-minute completed-run TTL, one active run per session and four active globally), polling endpoint for progress and cancellation. Browser POST starts run, GET polls, DELETE or POST cancel stops only its owned process, including EOF/error handling. Keep existing loopback Host/Origin enforcement and disable automatic real Agent invocation by default. CI adapter fixtures are explicitly test-only simulated process protocols; MCP tool workflows use actual SDK stdio/HTTP/SQLite product.

## View synchronization

When Agent tool operations complete, refresh current project summaries/plans/groups/routes without discarding unrelated UI state. Read resulting plan ID/revision and select its affected changes via the unified focus mechanism. New or modified nodes/edges become visible; latest user navigation/project selection overrides older run results. MCP proposals stay unapproved. Never overwrite dirty concurrent plan state or reuse an old snapshot as current.

## Test section

End-to-end actual authenticated model test is only run with existing credentials; never invent or borrow credentials.

## Options and decisions

Prefer subprocess JSONL adapter now over a new app-server transport: installed CLI protocol is inspectable, requires no new dependencies and has a small lifecycle surface. Keep provider interface so rich streaming transport can follow later. The existing forms are engineering UI, not conversational Agent; they move out of the default shell while preserving previous lifecycle coverage through opt-in controls. No keyword-to-form fake AI.

Approved-plan source implementation remains a separately ticketed execution mode (AG-02), because enabling source writes changes the approval/security boundary. Chat in this phase can inspect and actually change plans/groups through MCP; it must not claim source implementation when only a plan changed.

## Reviewed bridge boundaries and recovery

Independent review Important I1: Codex is invoked from a trusted empty temporary run cwd with --ignore-user-config and isolated MCP settings. Per invocation disable shell_tool, unified_exec, code_mode/code_mode_host, browser/computer use, apps/plugins/hooks and multi-agent; web_search disabled; MCP required=true and enabled_tools explicitly bounded. read-only sandbox supplements tool restrictions, not replaces them. Validate installed capability support; unsupported versions fail closed. Claude planning mode uses --tools '' and --strict-mcp-config, only after supported flag verification. No target-native cwd, shell command, unknown executable or prompt-only source guard. No user execpolicy/rules inheritance from target cwd.

I2: Chat MCP uses an immutable project binding plus channel-specific tool allowlist. Generic MCP's existing trusted-client mode remains unchanged. list_projects only returns the run's project; every tool rejects even valid foreign project/plan combinations. A run-owned loopback HTTP gateway also scopes plan reads/writes and records successfully committed mutation IDs/recovery data before forwarding responses. It cannot forward approvals or project opening. Requests validate normalized paths and bodies, and use service project ownership checks. Tool arguments cannot change scope.

I3: Cancellation stops the owned CLI process tree and owned MCP processes, waits bounded 2s grace then kills remaining owned tree; terminal state after cleanup. Completed/failed/cancelled/timed-out runs all trigger reread of current project state; journaled mutations focus identifiable actual changes, otherwise show 'may have saved changes' and reread without claiming ownership of concurrent mutations. Preserve partial createdPlanId. Browser start acknowledgement arriving after switch/unmount is immediately cancelled so a run handle is never lost. Read-after-cancel synchronization still obeys newer user navigation.

M1: HTTP Chat input includes optional scope {kind:'folder'|'file'|'function', path:string, nodeId?:string}, snapshotId and expected plan revision; service validates against captured project/plan. A scope is context data, never executable cwd. M2: one active run per project/channel (409 busy), max four globally (429 busy), bounds listed above; test repeats/two tabs and expiry.
