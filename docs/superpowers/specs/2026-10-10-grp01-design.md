# GRP-01: 圈选与可编辑函数分组

用户目标：圈选真实函数建立跨目录功能分组；同一函数可以属于多个组；编辑已有组并在重载、服务重启后保留。分组只修改知识数据，源文件字节与路径保持不变。现有知识语义改变使项目规划需要重新批准。

采用显式圈选模式而非普通点击或 Shift 手势：矩形选择与普通检查、漏斗双击和节点拖动分离；退出模式恢复已有图交互。React Flow selection 输入映射为真实 function 的 domain ID，排除 plan 层、去重，外部 Workspace IDs 为选择显示的权威来源，避免图投影更新丢失选择。已移动/待删除的真实节点仍可选。

Workspace 保存可编辑草稿 optional id、title、description、source、完整 memberIds，以及圈选 CodeNode[] 和编辑器显隐。编辑以已有 group.memberIds 全量初始化，页内名称绑定仅用于显示；未加载/缺失 ID 保留并允许显式删除。圈选加入执行集合并集。取消清空草稿但不保存。项目切换清空全部草稿与选择。圈选入口直接打开分组编辑器；高级导航保持原来首用结构。

HttpApi 和 Workspace saveGroup 传播 optional id，调用既有后端 upsert，保留 source。知识保存后重新读取组/规划，以服务器批准状态为准；仅刷新保存开始时仍然可见的当前组分页，异步不能覆盖新项目/新组/新快照。成员导航序号区分真实导航与绑定读取结果对象替换，快照不一致的绑定/缺失状态不控制当前草稿。

验收：>20 成员编辑不丢 ID；union、按 ID 删除、取消、项目切换；HTTP 编辑保持 ID、不新建组；真实浏览器矩形圈选、G1 跨目录、G2 共享成员、G1 编辑、重载及本任务自有服务重启、批准失效、源文件 bytes/path 不变。保留首用改动和 AGENTS，不改 indexer、不 commit/push/deploy、不停止其它进程。

自审：完整成员 ID 与分页解耦，缺失 ID 不静默丢弃；selection 与 inspection 分离；新增无需存储迁移。父设计代理已审查上述设计并认可。
