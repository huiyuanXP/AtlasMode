# KN-02 知识导出、迁移校验与冲突预览设计

日期：2026-10-10。状态：独立初审 REQUEST CHANGES C0/I3/M1 后的定向文档修订，等待原审查者复核；不是已实施功能，也不标票 DONE。原版 exact bytes/SHA 保存在 own review 目录 rev0-frozen。

## 1. 验收与范围

[KN-02](../../tickets/KN-02.md) 要求带 schemaVersion 的导出与迁移校验、先预览冲突再明确应用、不静默覆盖知识和历史批准。本设计针对已有项目的注释、功能组、目录职责及约束迁移，允许选择子集；可全量导出这些知识，但须明确包大小限制和未选择项。

知识包不是 [DATA-01](../../tickets/DATA-01.md) 的 SQLite 一致备份。项目、索引快照、浏览路线、视图布局、规划、批准、批准上下文、注释修订历史、POL intent/audit、settings 和凭据均不作为可导入记录。导出页面与导入页面固定展示“知识迁移不恢复规划、批准或数据库历史；完整备份见 DATA-01”。不执行包内内容，不写目标源码或运行编译/索引；目录域唯一可能的项目文件写入是已有 POL 管理的 `.codemap/structure.json`。

主控已确认两个明确应用域：注释/功能组的数据库批量事务；目录知识的 POL 队列与 finalize。两者分别确认、分别记录成功/失败/取消，不承诺整包原子性。第一域成功后第二域必须重新预览；取消第二域不回滚第一域。

## 3. 最小可迁移协议

新增 core `knowledge-package.ts` 定义严格 `KnowledgePackageV1`：

```ts
type KnowledgePackageV1 = {
  format: 'atlasmode-knowledge';
  schemaVersion: 1;
  exportedAt: string;
  origin: { projectId: string; projectName: string; snapshotId?: string };
  annotations: PortableAnnotation[];
  groups: PortableGroup[];
  directory?: {
    structure: StructureDocumentV1 | null;
    legacyPolicies: PortableLegacyPolicy[];
  };
};
type PortableAnnotation = {
  originId: string; originRevision: number;
  text: string; author: string; source: 'user' | 'agent'; isConstraint: boolean;
  reference?: { status: 'bound' | 'orphan'; kind: 'node' | 'relation';
    id: string; snapshotId: string;
    label?: string; filePath?: string; nodeKind?: string };
};
type PortableGroup = {
  originId: string; title: string; description: string;
  source: 'user' | 'agent'; memberIds: string[];
  composition?: PortableGroupComposition; // 运行时应用能力由 GRP-03 冻结接口决定
};
```

PortableGroupComposition 的协议形状是 `{kind:'capability'}` / `{kind:'sequence',order:string[],contract:string}` / `{kind:'wrapper',entryId:string}`，与已审 GRP03 设计一致，但不依赖尚不存在的公共类型。包语法合法但运行时尚无高级组能力时，preview 给该行 unsupported，可明确 skip 整组；语法混合/无效 order 仍是包校验错误。

PortableLegacyPolicy 复用 POL 的无 projectId 便携形状。注释 reference 是不可信来源提示，不是可直接写入的 Annotation.binding。origin 没有绝对 rootPath，不包含源码字节。时间/来源/原 revision 是 provenance，不能让客户端控制目标 createdAt/revision。可选 provenance 仅由上述 originId/revision/reference 提供；批准记录本身不进包，不承诺导出完整历史。UI 可展示当前本地批准引用作为只读说明，不发送批准上下文或导入通道。

新注释/组由服务生成 UUID 和目标项目归属。UI 导入创建的本地 source 为 user，来源包声称的 agent/user 留在服务生成的导入收据；编辑已有记录保留其 source，不借导入换来源。选择创建、编辑及绑定动作须在预览中明确。

导出只包含当前非删除注释、全部所选组以及已校验目录知识。墓碑、历史修订和历史审批不导出。已有 invalid/corrupt/不支持记录不能默默省略：全量导出返回带类型/ID 的阻断项，用户明确选合法子集才可导出。未加载成员仍完整保留其 ID；不会把分页前 20 项当全组。输入包的重复 originId（同类型内）、重复目录自然键、歧义规则键或重复 group memberIds 直接拒绝，不悄悄去重冲突内容。

所有顶层和注释/组字段严格，拒绝 approvals/plans/settings/approved-context/legacy-registry/history 等注入。POL 结构内允许的未知 JSON 字段由其 parser 无损保留；不把整个知识协议变成允许任意记录的扩展点。未知结构值是数据，不运行模板、脚本、模块或路径读取。

### 3.1 schemaVersion 与旧数据

包版本与 StructureDocumentV1.schemaVersion 是独立两层，都校验。当前没有已实现且可确认的历史便携 v0 文件协议，不能捏造转换规则。v1 经过纯校验/迁移入口 `migrateKnowledgePackage`，返回 `{sourceVersion:1,targetVersion:1,transforms:[],warnings}`；缺失版本、0、未知未来版本或未知必需字段 fail closed，零持久写。以后只有新增确切历史 schema 与 fixture 并获批准，才能添加纯转换器；转换后的内容/变动清单必须展示并重新预览后才应用。

当前旧持久组没有 composition 时按 capability 导出，读适配不改旧 JSON。若 GRP-03 尚未实施，包中含 sequence/wrapper 返回 UNSUPPORTED_GROUP_COMPOSITION，用户可跳过整组再预览，不能偷偷降级或截断高级字段。若已实施，直接复用其严格 GroupComposition 与 revision/CAS：sequence.order 是准确成员排列；wrapper.entryId 是真实当前函数；不导入 Plan.group_contract、must_reuse 或临时入口，不生成 calls。旧记录有未知字段/无法无损导出时报告阻断而非 strip。

### 3.2 有界输入与分页

| 边界 | 固定上限/行为 |
| --- | --- |
| UI 上传/导出原始 UTF-8 | 4 MiB；严格 UTF-8、重复 JSON key 拒绝；不接受 zip/SQLite；超限要求明确子集，不截断 |
| 全包结构 | 深度 32；250000 JSON values；注释+组+目录行合计 1000；任何 parse 前先检查 raw bytes |
| 单次应用 | 每域 100 个选中动作；超限保持预览要求分批，每批重新确认 |
| 注释内容 | KN-01 原限制：text 1–20000 非空；author 1–200 trimmed；ID 1–200 无控制字符；revision 正 safe integer |
| 新便携组 | title 1–2000 非空；description 0–20000；成员最多 200 个真实 ID；不改旧 capability 的兼容上限；旧组超过便携上限时阻断该整组导出，可明确跳过整组，不截断成员 |
| 路径/来源提示 | 规范 repo-relative path，最多 2048 字符；禁止绝对路径/控制字符/.. |
| POL 文件与 candidate | 沿用每份 1 MiB；仍校验整个 target candidate，而非只入包 delta |
| 预览 | 每页 20，最多 50；每页 JSON 输出最多 64 KiB；完整长文本用单项详情分页/有界详情，列表只摘要 |
| MCP | raw 包/导出内容最多 64 KiB，拒绝过大并给明确子集/UI 文件入口；preview 页同上 |
| token | 10 分钟有效；签名 payload 最多 16 KiB；不含所有记录或内容，只摘要/生成 ID/选择 digest |
| 导入收据 | 每域 JSON ≤256 KiB；只保存记录级映射和有界来源 reference，不重复保存全部成员映射/正文；应用前确认预算 |

值计数包含目录 unknown JSON；预算不能绕过未知字段。包导出超限失败，不下载半个合法包。限制不等于现有数据库扫描的内存保证：StoragePort.list 目前会物化整个 kind，全量枚举仍使用已有机制；本票只限制新包/动作/响应，不宣称解决全库分页或巨大 DB 性能。选定 ID 的详细内容尽量 get；真正全库流式扫描另立性能票，不引入泛化存储平台。

## 4. 冲突预览与明确映射

用户先选目标项目与应用域，上传包后得到版本报告和冲突页。默认所有动作 skip，不预选覆盖。每条显示来源、目标、before/after、绑定/成员/目录语义差异，状态 new/equal/conflict/unresolved/unsupported。选择有 keep（不改）、create（本地新 UUID）、replace（明确本地记录）三种；修改选择会废弃 token 并真实重新预览。

相同文字/标题/路径相似不是身份。跨项目、跨 snapshot 的 originId 不能被直接当目标 ID；即使 ID 字符串相同，仍需选择明确的目标记录/事实。不存在 fuzzy/global alias 自动重绑定。不按文本自动去重。已有服务生成的导入收据可以提供精确 origin packageHash+originId→targetId 建议，但必须再次选择；收据目标已删/更新时显示冲突。再次同一内容应用可显式 keep 或确认 equal，no-op 不造历史。

### 4.1 注释与组

创建注释默认 unbound，reference 提示留在导入收据。用户可明确选择“绑定当前项目/快照中的此节点或关系”；所有绑定交给 KN-01 selectAnnotationTarget 和 snapshot guard，缺失、不完整/不可用证据返回 unresolved。现有 orphan 不因旧 ID 重现被自动治愈；保持已有 binding 是默认，明确 rebind 才改变。replace 不能复活墓碑；需要另行 create 新身份。未选择/取消不写注释、修订、批准或导入收据。

组必须逐个来源成员显式映射为当前权威 snapshot 的真实 function；同项目同 snapshot 可提供 exact ID 建议但仍需用户确认映射。页面列出全部成员及缺失，分页不丢未加载项。缺失项可明确删除该来源成员后重新预览，不能自动 drop；若结果为空、成员失效或高级 order/entry 不合法，整组保持未提交预览，阻止该组选中应用。允许把该组 skip 而应用合法注释。入口不自动加入成员，顺序不根据真实 calls 推断。

组 replace 的 CAS 用实际 revision（GRP-03 已就绪时）及内容 digest；尚无 revision 的基线只使用完整规范内容 digest。annotation replace 使用实际 revision/墓碑状态。所有成员、entry、binding 再次在事务内校验，不依据当前画布范围。

### 4.2 目录知识

目录域有两个来源：合法 StructureDocumentV1 内的自然职责/allowed/forbidden/dependencyRules 和旧 DB-only legacy policies。预览清楚标记“文件权威 / 仅旧数据库 / 显式迁移”。folder 以规范 path 对应；规则以规范 from+mustNotImport 集合作键，不把相同 from 的不同约束悄悄合并；root unknown 属性、row unknown 属性的变化也必须列入差异。

新增自然 folder/rule 与选择替换的完整 row 更新受控文件 candidate；未选择行、未知字段及 root 扩展保持 target 原值。包里未出现的 target 项不删除。针对同一个 row 的 replace 必须明确展示将改变的未知属性；root unknown key 需单独明确选择。保留 `schemaVersion` 与 `x-atlasmode` 受控 schema，不能任意替换整个 reserved extension。legacy portable IDs 是来源提示，不冒用别的项目 policyId；新目标 legacy policy 生成本地身份。

已有 DB-only policy 可通过 POL 原控制分支更新而保持原文件字节；迁移到文件必须单独选择 explicit migrate，沿用 POL migration provenance 与删除原 DB record 的校验。两类选项可在一次目录批量中明确组合，但最终 candidate/DB patches 的来源和差异均展示。禁止绕过 POL 用 import storage.put('policies')，也禁止循环调用 updateStructure 造多个 revision。raw 文件错误/第三方变化、已有 pending/conflict、expected revision/hash 不符时整个目录域阻断，不能 fallback 到 DB-only“成功”。

## 5. 两阶段状态、CAS 与请求契约

拟新增服务接口（通过 workspace/public exports 接线）：

```ts
exportKnowledge(projectId, selection, transportBudget): Promise<KnowledgeExport>
previewKnowledgeImport(projectId, { packageText, domain, decisions, offset, limit }):
  Promise<KnowledgeImportPreview>
applyKnowledgeImport(projectId, { mutationId, packageText, domain, decisions, previewToken }):
  Promise<KnowledgeImportReceipt>
```

domain 只有 database / directory；itemKey 是类型+来源键的 SHA256（64 hex），避免原始长 ID 膨胀 token。来源键为注释/组/legacy 的 originId、folder 的规范 path、rule 的完整规范自然键、root unknown 的属性名。decisions 使用 `itemKey`、keep/create/replace、显式 targetId、完整成员/entry/binding 映射及目录 source 选择。记录原始和规范 package SHA256、选择 SHA256；同域两个选项指向同一目标记录或目录键时拒绝，不能最后一项覆盖前一项。相同内容的不同原始文件需要重新预览，不能把客户端提供的 hash 当证据。

服务签发 HMAC-SHA256 token，密钥启动时 randomBytes(32)，不来自包/浏览器；10 分钟过期，进程重启后旧 token 失效，客户端重预览。绑定 projectId/domain/packageRawHash/canonicalHash/decisionHash/generatedTargetIds/currentSnapshotId/knowledgeDigest/planStateDigest/structureRevision/fileDigest/importGeneration/expiry。digest 由服务读当前数据生成；knowledgeDigest 包含该项目注释 revision/绑定/墓碑、完整组语义及 legacy policies，planStateDigest 包含本项目现有 plan id/revision/status/approvalId。不包含其他项目或全部历史 key。视图/theme/layout 变化不构成知识冲突。

真正应用先验证项目访问权限、严格包/decisions 与预算并生成稳定 requestHash。进入现有 POL 同项目队列后按下面优先级分派；不得先认证新 preview token 再查 pending，也不得先调用 assertUsable/readStructure 而把可恢复 pending 挡住：

1. **可信 terminal 已存在：** 精确匹配 project/domain/mutationId/requestHash，返回不可变原 outcome，忽略旧 token 过期/重启失效。已终结 aborted/failed/conflicted 也只返回原非成功 outcome，不能拿同 ID 创建/复活 intent。不同 hash、domain 或 ownership 返回冲突；receipt 损坏/与对应 audit 不一致 fail closed，不 fallback 新请求。
2. **可信目录 pending intent 已存在而无 terminal：** 校验属于本项目、确为 knowledge-directory batch、mutationId/requestHash 精确一致，仅调用 POL 锁内既有恢复分支，即使原 token 过期或 HMAC key 已重启。patches、生成 ID、before/candidate bytes、actual expectedGuards 都从本地 intent 读取，不采用这次 payload/token 重新生成。未知/暂时不可读 I/O 保持 recovery_pending，未来同 hash 重试可再读；after 可证明且 guards 有效才 finalize 一次；before/third 等终态规则仍按 POL。不得另建 intent、再 publish、重签即自动重放或接纳另一包。不同 hash/来源/项目/损坏 intent 明确冲突或 recovery error，零新 publication。别的 pending mutation 阻断 new apply，不覆盖它。
3. **该 mutation absent，且无阻断的 pending：** 才要求新的有效 signed preview，随后锁内读最新 structure/recovery 并在同步事务重读 importGeneration/CAS/snapshot/项目/所选内容。failed/aborted/conflicted 的已知 ID 不属于 absent。无 token/expired/重启旧 token 拒绝新工作；只有新 mutationId+真实重预览+明确确认可创建新事务/intent。

任何新工作 guard 变化返回 STALE_IMPORT_PREVIEW（409）且不持久写，保留本地决策给用户重新预览确认。snapshot 更新即使当前全 unbound 也要求新预览。目录 prepare 与 finalize 也有 guards；pending 恢复只使用原 intent 的 guards（详见下一节）。

**I2 服务端的两域预览代次：** 固定服务命名空间 `settings/knowledge-import-generation:<projectId>` 保存严格 `{recordType:'knowledge_import_generation',projectId,generation}`；旧项目缺记录读为0，generation 必须是 0..MAX_SAFE_INTEGER 的 safe integer，损坏/项目不符 fail closed。preview 签入当前 importGeneration。每次实际 terminal success 或 no_op 与其 receipt 在同一次同步提交把 generation 加1；这是一条有界本项目迁移代次记录，不修改 knowledgeHash、plan revision、注释修订、approval/context/legacy registry。生成代次只使该项目所有此前迁移 preview 过时，不影响别项目或 view-only 变动；无需 flow/session 平台。允许这种保守失效，即使另一个包或同一域的旧 preview 也须重新确认。

数据库域正常/no_op提交及目录的无发布事务/有发布 finalize 都必须原子保存 receipt+generation；rollback、pending、failed/aborted/conflicted、不曾 apply 的取消不递增。terminal lost-ACK/restart replay 不再次递增；pending recovery 的首次成功 finalize 才递增一次。代次容量在新请求 prepare 前检查，溢出整个域 fail closed；有发布 intent 记录捕获的 expectedGeneration 与 expectedNextGeneration，在 finalize/recovery 中再次核对，不能因原代次变动 force overwrite。所有协作新导入继续同 POL queue，无法恢复的 pending 阻断另一个域的新导入。

因此“先预览两域 → 第一域 equal/no_op 明确应用 → raw HTTP 使用原第二 token”在服务端必得409；第一域 receipt 已成功且代次改变，UI 丢 token 只是显示控制。第二域必须真实 fresh preview+明确确认。两种域顺序、no_op、ACK丢失重试与重启都有对应测试。

同一项目普通知识、批准与目录流程使用现有 POL 串行边界；不得另建 import queue，也不得 await 于 SQLite transaction。readStructure 可能按已有规则同步用户外部修改的文件，这属于 POL 正常外部同步，不称“取消导入产生的写入”；取消绝不应用包内容，也不逆转已发生的外部同步。

混合包 UI 状态：已预览 → 明确应用数据库域 → 数据库成功收据 → 第二域待重新预览 → 明确应用目录域 → 每域结果。次序不强制，先应用目录也要求另一域重新预览。第一域 no-op 仍强制重新预览另一域以显示最新 guards。不复用此前 token。用户能关闭第二阶段，页面保留“数据库域已成功；目录域未应用”，不能显示整包完成。

## 6. 数据库域：单事务与一次失效

新增受控 `KnowledgeTransfer` 编排与 KN 事务内 mutation bridge。桥由 KN 所有者提供：验证 content/binding/CAS 后生成严格本地 Annotation 和不可变修订；不会导入传来的 history/revision/time。组合编辑+显式绑定可以在同一次 revision 中记录最终 Annotation（内容有变 action edit；仅绑定 action bind/detach；create action create）；完整导入决策在不可变导入收据记录。无需修改既有一般注释 API 行为或增加客户端可写的历史 action。

单个同步 storage.transaction 包含：全项校验与 generation 容量 → 写注释及其新修订 → 写组 → 服务生成收据与 importGeneration+1 → 有实质语义变化时 invalidateProjectPlans 恰好一次。所有当前本项目 plans 各加一次 revision 并回 draft，历史批准原记录/冻结上下文/legacy registry 不改。任一项失败、UUID/revision-history key 冲突、receipt 写失败都 rollback 全数据库域；其余项目/目录原始文件不变。明确确认的非空 equal 选择可成为 no_op：不生成多余知识修订，不 invalidate，但必须原子提交 no_op 收据与 generation+1，使 sibling preview 过时。零所选动作的 raw apply 拒绝，preview/取消不写代次。

requestHash 固定为服务规范化的 projectId/domain/packageRawHash/canonicalHash/decisionHash，不含 token 字节、expiry 或服务生成 UUID；重启后同一确定请求可以匹配既有收据，不依赖旧密钥。generatedTargetIds 只用于首次 apply 的签名校验与已有收据结果，不能被客户端替换。

收据 key 固定 `settings/knowledge-import:<projectId>:<mutationId>`，由服务控制，客户只能提供规范 UUID mutationId。包含 requestHash、domain/outcome、packageHash、实际记录级 origin→target 映射及有界注释来源 reference、被改记录/revisions、affectedPlans、完成时间；最多本次 100 动作且 256 KiB，不拷贝整包/历史/notes 文本或完整组成员映射；before/after 真正内容由本地记录/修订读取。所有预算配置只能收紧固定上限，不能由 HTTP/MCP 参数扩大。相同 mutationId+同 requestHash 返回既有结果（包括重启后），不同请求占同 ID 返回冲突；不重写收据或再次 invalidate。不得通过包提供设置 key、伪造旧收据、升级批准或添加 legacy allowance。

## 7. 目录域：复用 POL 发布与恢复

新增 `StructureSync.applyDirectoryImport(projectId, input)` 公开入口自行进入已有 enqueue。内部用该锁内的 read/recovery 和纯 candidate generator；不得调用会再次入队的 updateStructure。拟新增一个受控 `StructureOperation` 批量目录 import 变体，只存 ≤100 个目录 patch、package/decision hashes、expected legacy policy digests/source decisions 与知识/snapshot/plan guards，不存注释/功能组/任意 settings。

POL 所有者需让 prepare 持久 intent 包含必要 legacy before/after patches 并验证整个 candidate。已有原始 beforeBytes/candidateBytes、digest、revision、source=ui 沿用；不伪造 audit source。单目录批量至多一次 publication/一次 finalize。invalidate 触发是三者的逻辑 OR：文件语义变化、DB-only policy 实质编辑、非空实际 legacy 来源迁移；混合批也只 invalidate 一次。首次真实文件引入等既有 POL 上下文规则不放宽。纯 DB-only 编辑复用现控制分支；如果等值 extension 已覆盖所选 legacy 记录而文件/语义摘要不变，但实际仍需移除非空 DB 来源，按 POL 既有 **无发布同步 finalize**：复读并核对所选 ID/owner/完整 before-values，仅删所选旧来源，保存迁移 source-transition audit/import receipt/generation+1，structureRevision 和本项目 current plans 各+1，原批准/history 不改；原文件 bytes/digest 完全不变、不调用 publish、不创建 beforeDigest==afterDigest 的含糊 publication intent。零迁移且所有值不变才是 no_op，不改 structure/plan revision，但终态收据仍推进迁移代次一次。

同时有真实 file semantic change+DB edits+migration 的批量，只把全部捕获 DB patches/migration deletes 放在同一次 publication finalize，不能提前半写；其三触发逻辑 OR 只失效一次。只是 serializer 格式/排序的候选变化不能强制等值 source-only 分支重写原文件。

发布遵循 POL：prepare 后同目录临时写/flush/close → 复读 beforeDigest → rename → 实读 candidate hash → 一个同步 finalize 保存 projection、所选 DB patches/migration deletions、audit/receipt/terminal intent、importGeneration+1 及按三触发逻辑 OR 的一次 invalidate。prepare/finalize 重读该批的 expected legacy values、项目 snapshot 和知识/plan guard，禁止过时覆盖。其他同项目协作修改受同一 queue 阻挡；若进程外/不守队列修改 DB 导致 finalize guards 变化，保留 recovery_pending/conflict，不用包内容 force 覆盖。

故障语义沿用现有 POL：rename 前失败无知识应用；rename 后 DB finalize 失败报告 recovery_pending，文件可能已改变，不能标成功或宣称 rollback。重启磁盘等于 after → 校验 guards 后 finalize 一次；等于 before → abort 不自动重放；第三版本/坏文件 → conflict 保留原磁盘和 pending intent。不能自动用 beforeBytes 覆盖用户更新。第二域取消只能发生发布前；发布后的关闭页面不撤销 intent，用户能查看恢复收据。受控取消准备未发布的 intent 仍需证明 beforeDigest。现有单写者/原始文件 TOCTOU 限制如实保留，不称 OS 原子 compare-and-swap。

目录同 mutationId 的 pending 重试在新 token 验证前按 §5 的三分支规则只恢复既有受控 intent，不根据过期 token 新建/重放请求；unknown I/O 后可再次同 hash 恢复，完成后返回本地终态；terminal replay 不再推进 generation。目录 no-op 返回 POL 终态 no-op 收据并能作为 KnowledgeImportReceipt 读取；有 publication 的 import receipt 与 POL finalize 同事务落盘，不能另写“成功”后丢终态。receipt 幂等统一按 mutationId/上述稳定 requestHash；POL owner 为目录 batch 保持这层请求标识，与 prepare/finalize 的 actual expectedGuards 分开，不能因重签 token 把同 mutationId 当不同包内容。恢复时不再重复失效。不会引入跨域恢复平台或把大量注释塞入 POL intent。

## 8. 真实入口与交互

Advanced 知识区增加“导出/导入知识”入口，保留现有 Notes/Groups/Policies、圈选、组折叠、inspection、FS 流程；不靠隐藏高级按钮满足验收。导出支持全知识或显式选择，显示完整计数、范围与大小，下载 knowledge.json（用户自行决定保存为 `.codemap/knowledge.json`，应用不自动覆写它）。导入实际文件输入/拖入、版本报告、冲突分页与单项差异、绑定/全成员映射、分域明确确认/取消、过时重预览和收据查看必须接真实 HTTP。

确认按钮写明“应用所选 N 项注释/功能组”或“应用所选 N 项目录知识”，说明该域会使当前规划待确认，历史批准保留。未选择、无效组选中、版本不支持、文件 recovery_pending、stale token 时按钮不可提交并显示具体原因；不静默切域/漏项。项目切换取消 in-flight UI 的展示资格，清空旧 draft/token；旧请求返回不得覆盖新项目状态。长文摘要不改变真实内容，中文/英文、键盘和窄屏可完成流程。

HTTP：新增项目 scoped export、preview POST、apply POST、receipt GET；已有服务权限/项目验证保持。导出 attachment 用原始 UTF-8 预算；preview/detail 返回有界 JSON。HTTP 不提供直接 records 导入/覆盖端点。

MCP 新增真实 `export_knowledge` 与 `preview_knowledge_import`，列入 readOnlyTools，复用同一 HTTP/service 校验与 project-bound allowedTools，明确 64 KiB 限制；超限显示选择子集或 UI 文件入口。MCP 无 apply/rebind/approve 工具，不让 Agent 自动应用包；应用由用户显式 UI/受现有权限约束的 HTTP 确认完成。已有 propose_group 保持语义。SDK 实测 tool listing、导出、冲突页、foreign project 拒绝和无写入；不因 MCP readOnlyHint 就省掉服务验证。
