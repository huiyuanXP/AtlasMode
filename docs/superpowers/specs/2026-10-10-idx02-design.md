# IDX-02 captured workspace package source mapping
Authority: docs/tickets/IDX-02.md; current AGENTS autonomous execution exception. No new external dependency, runtime loader, target execution, project references, or core/service API.

Alternatives: expose all captured names globally (rejected: sibling workspace leakage); synthesize node_modules with TypeScript resolution (rejected: conditions/type declarations/fallback can silently cross evidence boundaries); use a small captured registry before existing configuration resolution (selected: deterministic and reviewable).

Captured inputs: scanner already captures eligible package.json under 512 files/256KiB single/4MiB total budgets and hashes exact bytes in v3. Reuse these inputs and unavailable-manifest boundaries, including workspaces/exports bytes; no extra disk reads.
Workspace authorization: workspaces arrays (or object packages array) support literal directory patterns and * matching one directory segment. Reject unsupported glob syntax/traversal. Membership is from captured manifest directory, unique package names only. The nearest workspace owner applies; consumer's nearest package must be owner or a registered member. Unlisted/nested packages cannot borrow an ancestor registry. Package self-reference uses its own nearest manifest and explicit exports.
Exports: explicit root strings, exact subpath strings, and deterministic single-star subpaths. Exact key wins; pattern selection uses longest prefix then longest suffix. Targets must start ./, stay within package directory and its own nearest captured package boundary, contain no traversal/node_modules/URL/encoded segments, and name a captured implementation source exactly. No main/index fallback and no guessed dist-to-src or extension substitution.
Conditions: literal import/export syntax establishes import; literal unshadowed require or import-equals establishes require (existing CommonJS semantic guard still decides call identity). For a specifier with mixed request syntax, compute both environments and require convergence. Ordered import/require/default branches follow known activity; all other conditions are unknown, so evaluate enabled and disabled alternatives including blocked/invalid/missing-target outcomes. Nested NO_MATCH continues the parent next key; it is distinct from BLOCKED/INVALID, which must never fall back. Reject integer conditional keys. Bound evaluation to 16 object levels and 2048 work units per request; overflow is unknown with diagnostic. Accept only when every possible outcome is the same authorized source. Arrays, null, invalid mixed export shapes and divergent/uncertain conditions stay unknown. This supports deterministic conditions, not arbitrary Node flags or loader execution.
Unknown classification: known captured package names with missing/unauthorized mapping remain unresolved with package diagnostics, rather than external. Truly uncaptured bare imports retain existing external classification. Invalid nearest manifests stay opaque. Explicit configured tsconfig paths take precedence and do not fall back to workspace on failure.
Implementation: new workspaceResolution.ts consumes captured SourceFile[] and returns resolve(sourcePath,specifier) {known,targetPath?,reason?}, recognizes(specifier), diagnostics. Add optional final manifests parameter to indexTypeScript; SourceIndexer passes existing scan.manifests. createConfigurationResolver takes optional registry and returns captured mappings through existing ts-morph resolutionHost. Existing CommonJS configuredAlias callback receives combined configured/workspace recognition. Preserve declaration IDs, physical target file imports and all IDX01 guard semantics.
Evidence: test root/subpath/pattern, conditional request split/convergence/divergence/order, duplicate names, nested/unregistered consumers, missing/excluded/symlink/invalid targets and no checker fallback. Real compiled HTTP/MCP/UI fixture proves source identity, package-only exports/workspaces changes stale approvals/routes and immutable SQLite history, cross-project isolation. Real AtlasMode readonly capture confirms dist/conditional limitations explicitly. IDX01 349 baseline plus new tests and fresh Express strict gate if resolution changes affect it.
Self-review: package bytes already included in freshness; no schema or hash format needed. Registry must run before normal TS package lookup, but after explicit paths precedence. Known rejected mappings cannot leak via external/checker fallback. Conditions no longer blanket-rejected; support bounded static selection/convergence. Runtime compatibility remains a documented non-goal.
Primary semantics: https://nodejs.org/docs/latest-v24.x/api/packages.html and https://docs.npmjs.com/cli/v11/using-npm/workspaces/ .

Final review amendments: requested subpaths and forbidden node_modules segments are validated before fixed wildcard target selection; wildcard matches require at least one character. Opaque invalid/unavailable manifests retain their boundaries and known package names but confer no source mapping authority. Type-only namespace and re-export chains cannot establish runtime callable identity. Unshadowed require mode selection excludes captured lexical bindings. Wildcard substitution preserves own __proto__ keys via null-prototype records and has its own bounded traversal. Final evidence and explicit limitations: ../reviews/idx02-2026-10-10/README.md.
