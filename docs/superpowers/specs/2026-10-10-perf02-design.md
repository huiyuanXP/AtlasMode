## 方案选择与最小 slice

选择有界最小全目标数据 + Web Worker 纯布局 + 原局部渲染。它让固定 Express/Flask有机会得到全局拓扑位置，同时不把几千卡片全部塞入 React Flow，也不把源码/完整snapshot或全图送给 Agent。

仅给当前80/300子集排布成本最低，却无法满足全项目目标；只适合作为明确标识的降级。直接全量渲染或新增 elkjs 可扩大能力，但增加依赖、打包与呈现成本，本 slice 不采用。若固定真实目标在本设计预算内仍无法通过，保留失败并让独立审查决定调整预算/算法；不能悄悄改“全局”为loaded以过票。

范围：新只读 layout-target query；不含事实的布局数据提取；确定性 SCC/分层位置；受限 worker生命周期；当前范围的紧凑呈现和镜像位置；默认自动位置、显式重排、手动位置恢复；真实规模/几何/不变性证据。没有 source writer/IDX-04迁移、规划操作/schema变化、审批新流程、MCP新工具、导入全仓上下文、增量索引或边路由引擎。

## 完整目标只读契约

新 `POST /api/projects/:id/layout-target`，strict body **仅** `{expectedSnapshotId: string}`，非空当前 snapshot ID，调用方不能提高 hard cap。路由取 `service.getSnapshot(projectId)` **一次**，在同一个捕获对象上校验 id、计数、提取与序列化；不先 summary 再假定另一个GET仍同 snapshot。不匹配沿用 `SNAPSHOT_CHANGED`/409；不存在项目按已有404。读不刷新、不解析源码、不写DB、不使plan失效。

新纯 query helper `packages/core/src/layout-target.ts` 定义类型和 `getLayoutTarget(snapshot: CodeSnapshot, expectedSnapshotId: string): LayoutTargetResult`；它是事实查询而非 UI 布局。由 `apps/server/src/queries.ts` 装配，route只作strict解析。公共出口只在主控授权窗口合并。

```ts
type LayoutFact = { id: string; kind: CodeNode['kind']; parentId?: string };
type LayoutRelation = Pick<Relation, 'id' | 'sourceId' | 'targetId' | 'type' | 'resolution'>;
type LayoutCounts = { nodes: number; relations: number; byKind: Record<CodeNode['kind'], number> };
type LayoutTargetResult = {
  projectId: string; snapshotId: string; contentHash: string;
  scope: 'project_indexed_facts'; counts: LayoutCounts;
  limits: { nodes: 5000; relations: 20000; bytes: 8388608 };
} & (
  { status: 'ready'; complete: true; nodes: LayoutFact[]; relations: LayoutRelation[] }
  | { status: 'rejected'; reason: 'node_budget' | 'relation_budget' | 'byte_budget'; actualBytes?: number }
);
```

总量来自 `snapshot.nodes.length`/`relations.length`，不是 summary入口数或 graph union；byKind includes actual external。ready必须每个真实 nodeID、每个 raw relationID各出现一次，拒绝重复id/不存在非null端点的不一致snapshot而不生成布局。保留 raw unresolved/external关系的身份和计数，但它们不会被升级成 resolved rank constraint。null target保持null，不制造外部卡片。只传id/kind/parentId与上述关系字段；**不传 name/signature/filePath/evidence.text/content/source全文/annotations**。显示/点击/evidence/source仍走原有局部事实接口。父路径事实的parentId只供排序亲和，不生成contains或改所有权。

5001 nodes或20001 raw relations立即返回rejected与**同一snapshot真实总量**，无截断 nodes/relations。ready JSON的UTF-8字节数（整个响应）超过8MiB则 byte_budget，actualBytes记录实际大小，不假报较小。核心用TextEncoder计数，无Node-only Buffer依赖；固定字符串ID可使byte预算先于node预算被触发，必须测。HttpApi仅此新请求用有界body reader，累计读取实际UTF-8响应超过8388608 bytes即拒绝/abort；Content-Length仅用于预检，不能单靠header或在无界response.json之后声称transport有界。旧接口解析不变。UI保留原局部graph、位置与手动pins，明确“全项目自动布局未完成：事实N/5000，关系E/20000，原因…”；不会自动提高cap或请求unbounded snapshot。拒绝不是布局成功，也不改用户positions。

## 独占纯 helper 接口与算法

新 `apps/web/src/features/graph/overview-layout.ts`，无React、DB、fetch、DOM、source、worker全局副作用，接口用只读值，不突变输入：

```ts
type XY = { x: number; y: number };
type LayoutBox = { width: number; height: number };
type GlobalLayoutInput = {
  target: Extract<LayoutTargetResult, {status:'ready'}>;
  pins: Record<string, XY>; // actual domainId keys, mapped from existing fact:<domainId>
  retained: Record<string, XY>; // same-project surviving auto coordinates; not persisted
};
type GlobalLayoutResult =
  | {status:'ready'; positions: Record<string, XY>; ranks: Record<string,number>;
     order: string[]; stats: {nodes:number;rawRelations:number;rankRelations:number;sccs:number;geometry:GeometryWork};
     manualOverlaps:ManualOverlapDiagnostics}
  | {status:'rejected'; reason:'invalid_input'|'work_budget'|'geometry_budget';
     stage:string; geometry:GeometryWork; manualOverlaps:ManualOverlapDiagnostics};
function layoutProjectFacts(input: GlobalLayoutInput): GlobalLayoutResult;
```

Global positions keys为**实际域id**（没有alias）；pins/retained从实际fact渲染key精确映射到域id。controller只映射存在target.nodes的 `fact:<id>`，不解析任意冒号字符串、不把group或plan key当域id；所有未识别saved keys保留原ViewState。

确定算法：sort真实id；以 **resolved calls/imports、存在且kind不是external的真实两端**建立去重方向约束，按(source,target)去重只用于rank，raw计数不变；contains、unknown/external、null不进入依赖rank。使用**迭代**SCC，避免5000长链递归溢出；condense DAG按稳定id topological order，最长路径rank，保留cycle摘要不声称cycle消失。rank内用两次（前向/反向各一次）稳定邻接平均序位排序，高入度目标的调用方相邻；同权重以id打破平局。构造邻接/SCC/condensation为O(V+E)，排序为O(VlogV+E)，两次sweep有界；不宣称含排序/placement全部严格O(V+E)。

全局自动位置采用列宽400、行高300、最小卡片gap48的保守格点，默认fact box300×220。文件/文件夹在独立结构带按真实parent链稳定排序，external在独立已知外部带，孤立函数与call components按最小域id稳定打包；结构带不伪装依赖rank。组件边界、内部cycle、父链cycle处理均有确定结果。manual pins绝对坐标原样保留；retained自动点在同project下一snapshot仍存活且未显式重算时作为保留点，避免每次refresh重新排现有卡片。新事实按rank附近空格放入，未知旧域id位置不删除。新manual pin或实际尺寸校正与retained auto点冲突时，仅冲突auto点释放保留并重新找空位；saved pin优先，不能把retained auto误列为manual-overlap而跳过碰撞验证。

占用表使用 cell bucket，但 bucket 数量不是碰撞工作证明。全局 worker 和局部同步 helper 共享以下工作计数语义，所有 pins 插入/已有 retained 点复核/自动候选检测/最终几何验证都消耗同一 job budget；不得在每个节点、每个阶段、每个桶或第二次测量校正时重置。循环在读取下一个元素或执行下一次比较**之前**检查并计数，恰好到 cap 可完成，下一步将超 cap 时返回 work_budget、stage、实际已消耗计数；没有部分 ready/positions/apply/save。每次 ready 必须已经完成最终验证，不能以“诊断稍后完成”假 ready。

| 硬计数（仍为待实测提案） | 全局 worker job | 当前局部 job（最多两次校正累计） |
| --- | --- | --- |
| 每 auto 点每 pass 候选数 | 32 | 32 |
| candidateProbes 累计 | 160000 | 32000 |
| 单 box 占用 cell 数 | 64 | 64 |
| cellEntriesInserted 累计 / 同时驻留 entries | 200000 / 200000 | 40000 / 20000 |
| bucketEntryVisits 累计 | 4000000 | 200000 |
| rectangleComparisons 累计 | 1000000 | 50000 |
| manualPairObservations（每 pass 最终验证的唯一相交 pin pair，跨 pass 累计） | 4096 | 256 |
| diagnostic output | 64 affected pin IDs + 32 sample pairs | 64 affected pin IDs + 32 sample pairs |

固定 cell 边长512 world units。几何 gap 检测使用扩张 gap48 后的矩形，manual→manual 的诊断用原矩形；所有尺寸、cell 坐标及范围须 finite/safe，越界为 geometry_budget。一次 bucket 中取出一个 entry 就计 bucketEntryVisits，即使该 entry 属于自己、在别的 cell 已遇过或下一步会去重；对两个矩形实际执行相交谓词才计 rectangleComparisons。每次查询的 visited-ID Set 只容纳当前受限目标的 IDs（全局5000/局部500），避免重复矩形比较，但不能隐藏重复 entry visits；不得先 flatMap/复制整个桶后计数。每个 box 最多64 cells，候选、插入与最终验证的所有遍历因此都有独立计数；final validation 也用同一索引与 budget，不能额外执行未计数的全 pairs 检查。边只约束 rank/order，碰撞检测不采样每条长边上的 points 或建立无界 edge cells；高 degree/长边仍计入 raw/route 与投影工作预算。

```ts
type GeometryWork = { candidateProbes:number; cellEntriesInserted:number;
  liveCellEntries:number; bucketEntryVisits:number; rectangleComparisons:number;
  manualPairObservations:number; passes:number };
type ManualOverlapDiagnostics = { affectedPinIds:string[]; samplePairs:[string,string][];
  pairsObserved:number; complete:boolean; truncated:boolean };
```

诊断只在每 pass 的最终验证阶段计唯一 manual pairs：按稳定 visual/domain ID 顺序，查询去重后只检查 ID 大于自己的 pair，不建立无限 pair Set。所有初始 pin/retained 插入检测仍计 visits/comparisons，但不重复增加最终 pairsObserved。samplePairs 最多32、affectedPinIds 最多64，达到**输出**上限后停止追加而继续受硬计数保护的验证；完整验证成功时 pairsObserved 是该最终 pass 的准确总数、complete=true，truncated 表示样本或 IDs 未全部列出，不是事实被截断。GeometryWork.manualPairObservations 是每 pass 观察次数之和，同一 pair 在第二 pass 被检查会再次消耗 job cap，不得凭跨 pass 去重免除真实工作。若 manualPairObservations 或其它 work cap 耗尽，结果 rejected、complete=false、pairsObserved 只是当前 pass 已观察下界，不能显示为总重叠数或成功诊断。零相交的同桶 pins 仍消耗实际 entry visits 与 rectangleComparisons，不能以 pairsObserved=0 声称 O(N)。

saved manual pins 始终原样保留；允许 manual→manual 重叠并有上述有界提示，自动点不得撞 pin 或其它 auto。新 pin 撞 retained auto 时只释放冲突 auto，检查与重新放置也消耗同一 budget。非finite输入、过大/不安全 cell 范围拒绝自动布局，不把坐标归零。拒绝不 PUT view、不移动或丢弃任意 saved/offscope key；旧 accepted safe projection 可保留，但明确旧范围/本次未完成。数值只有真实计时与 adversarial fixtures 后才可冻结为能力，不声称哈希表本身保证无二次行为。

## Worker、代次与实时预算

新 `overview-layout.worker.ts` 只调用helper；新 `overview-layout-controller.ts` 管理一个项目一个active worker，采用Vite既有 `new Worker(new URL('./overview-layout.worker.ts', import.meta.url), {type:'module'})`。没有新依赖或shared daemon。request/reply token精确为 `{projectId,snapshotId,layoutGeneration,viewGeneration}`；UI当前project/current summary snapshot/token必须全等，且target.projectId/contentHash与已接收summary一致，否则丢弃。不能用迟到全局结果覆盖用户刚拖动的pin。

controller结果契约为 `OverviewWorkerOutcome = {status:'completed';result:GlobalLayoutResult;computeMilliseconds:number} | {status:'failed';reason:'timeout'|'worker_error'|'unsupported'}`；helper拒绝与worker故障均不会当作ready。不存在Worker时明确unsupported，不能在主线程同步全局fallback。

worker计算预算提案：硬墙钟1000ms（含worker启动/structured clone/计算/回传），到期terminate并展示timeout，取消/project change/refresh/new pin/recompute同样terminate旧worker；晚reply仍按token拒绝。一旦拒绝不会循环每render重试，只有目标代次变化或显式“重算自动布局”才新请求。纯helper有限work预算提供可复现拒绝，墙钟由controller守住，不能只用promise超时让后台继续耗CPU。默认同project保留上一可用auto positions，旧snapshot结果只作明确旧范围fallback，不能作为当前snapshot完整结果；本次新snapshot无法完成时不扩用旧结果覆盖新事实。

性能接受目标（非已测能力）：固定Express/Flask冷/热各5次，10次全部ready；记录query耗时/transport bytes/worker launch+roundtrip/纯compute/主线程long tasks；纯compute p95≤250ms，wall roundtrip每次<1000ms。拒绝、超时或超过目标都保留原FAIL，票不能凭“有timeout”标DONE。VM2/browser/version/source freeze/target commit/CPU必须入收据。真实总nodes包括external、rawrelations包括unknown；不能只测320条resolved关系就声称处理15216条完整事实关系。

## 当前范围呈现、group镜像与测量

全项目worker计算每个事实的全局位置/rank/order；**渲染仍原80/300事实nodes与240/900关系查询**。初始seed、局部expand、file/folder导航、焦点/计划anchors预算保持。新 `overview-visual.ts` 将最终display projection与全项目rank/order映射成当前范围的紧凑坐标：压紧未显示的空rank/行，但保留全局rank与排序关系；auto coordinates因此是全项目结果的**范围呈现**，不能声称当前显示了全部项目。首次当前scope以global位置为seed，后续同scope新节点只补空位，既有自动点保持；scope变化可以重新压紧未保存auto点，手动pins永远固定。局部紧凑坐标不改global facts/IDs，scope状态与generation另计。

```ts
  membershipVisits:number; projectionStepsUpperBound:number; visualAllocationsUpperBound:number };
type ProjectionEstimate = {

} & ({status:'ready';countStatus:'complete';nodes:number;edgeUpperBound:number}
  | {status:'rejected';reason:'node_budget'|'edge_budget'|'operation_budget'|'reference_budget'|
      'projection_work'|'membership_work'|'invalid_input';countStatus:'complete'|'partial_lower_bound';
      nodes?:number;edgeUpperBound?:number;nodesLowerBound:number;edgesLowerBound:number});
function estimateBaseVisualWork(graph: SubgraphResult|undefined, operations:readonly Operation[],
  filter:LayerFilter, referenceNodes:readonly CodeNode[]): ProjectionEstimate;
function estimateVisualWork(base: Projection, groups: readonly FunctionGroup[],
  collapsedIds: readonly string[]): ProjectionEstimate;
function layoutVisibleOverview(input: {projection:Projection; global:Extract<GlobalLayoutResult,{status:'ready'}>;
  pins:ReturnType<typeof resolveVisualPins>; retained:Record<string,XY>;
  measurements:Record<string,LayoutBox>; ignorePinsFor:readonly string[];
  priorGeometry:Readonly<GeometryWork>}):
  | {status:'ready';positions:Record<string,XY>;manualOverlaps:ManualOverlapDiagnostics;geometry:GeometryWork}
  | {status:'rejected';reason:'visual_budget'|'work_budget'|'geometry_budget';stage:string;
     actual:{nodes:number;edges:number};geometry:GeometryWork;manualOverlaps:ManualOverlapDiagnostics};
```

Projection类型复用graph nodes/edges/notices。`ignorePinsFor`只能由用户显式重排当前visual IDs产生，默认空。priorGeometry 首 pass 为全部零值，第二 pass 必须传入首 pass 返回的累计计数；helper 复制它后继续计数、passes递增，绝不突变参数。OverviewSession 持有同job累计计数，UI只在完整job结束后宣布ready；不能通过重新调用helper拿零值逃避第二pass预算。`resolveVisualPins`首选saved visualID；若first ordered group alias无自己的key，复用GRP-02的首alias `fact:<domainId>` fallback，并明确sourceKey；其余镜像不继承该canonical位置。header=`group:<groupId>`，alias=`group-member:<groupId>:<domainId>`，它们属于视图，`data.node.id/filePath/parentId`继续真实函数。layout不写`node.position`以外任何字段，不重新命名fact、不造contains、不将group设成React Flow/domain parent、不增加真事实/关系。

**在 projectGraph 之前**，先检查数组 length，不使用 map/filter/flatMap 构造 visibleOps 或 projected nodes/edges。现有 Plan.operations 没有 schema cap，本票不改变它。filter=fact 时 visibleOperations=0，storedOperations 仍显示真实 length，但不扫描或传入 operations；filter=plan/both 才检查 visibleOperations≤4096，超过即 operation_budget，以 length 给 exact stored/visible 数量、operationVisits=0，不为了“总数”先遍历整份大计划。graph 原始 nodes≤300/relations≤900、referenceNodes≤500 才进入 preflight；超限在复制或扫描前拒绝，不能通过截断更大的输入为 ready。无图的计划视图也受同样保护。

preflight 在这些 length caps 内最多两次 operation pass（最多8192 actual operationVisits）、两次 raw graph relation pass（最多1800 relationVisits）、两次 graph-node pass（最多600）、一次 reference pass（最多500 referenceVisits）。第一 pass 建 bounded引用/kind/按ID计数索引，随后在完整已知endpoint集合上第二 pass 计 planned edges；不以单次遍历口号掩盖实际二次访问。按现役 referenced/anchor/filter/端点语义计算 emitted node 数和 base edge 上界，包括每个 add_function 与 endpoint-present add_relation。计**实际分配次数**，不能以 unique domain ID 减掉重复 emission；非法 visual-ID 冲突拒绝 invalid_input。仅构造受限的 ID/kind/count 索引，不调用 projectGraph/addNode、不创建 ReactFlow nodes/edges/changes/notices。达到501个 emitted nodes或2001条 base edge 下界立刻停，countStatus=partial_lower_bound，显示“至少…（尚未投影）”；完成扫描才标 complete。source 数组 length 永远是 exact，不把早停下界标实际完成数。两 loaded endpoints+2001 个合法 add_relation 必须在第2001个有效计划 edge 处 edge_budget，**projectGraph 调用次数为0、edge array 分配次数为0**。其编辑内容和全项目事实 worker 不受视觉拒绝修改。

不能只限制 node/edge 数而放行 nested scans。现役 changes 每 emitted node 扫 P operations，matching move 会 findLast(P)；effectiveFunctionPath 每 addition 最多两个 P 扫描；remove_relation 引用最多扫 R，事实边 removal 标记也扫 P。因此在已计数的 N emitted nodes、P visibleOps、A additions、D remove_relation ops、F endpoint-present fact edges、C=所有 emitted node 对应的 matching move 总次数、R raw graph relations、Q references 上，记录保守 `projectionStepsUpperBound = 16*(graphNodes+R+Q+P+N+edgeUpperBound) + N*P + C*P + 2*A*P + D*R + F*P`。纯 helper 用 bounded maps 一次计 C/A/D/F，不自己运行这些 nested scans；安全整数饱和到 cap+1 即拒绝。cap **2000000 steps**，visual allocations 上界同时为 nodes+edges+notices+changeEntries，cap **10000 entries**（notices≤R+P；changeEntries 按各 emitted node 实际相关 annotate/remove/move 次数的保守计数）。这两个 cap、operation visits 和 edge/node cap 都必须 ready 才可调用未经改写的 projectGraph；上界不是实际执行计数，UI/收据不得混称。大量不增加节点的 annotate/move/remove 操作也能拒绝，不能以2000条edge后置检查掩盖 CPU 工作。本修复不重构旧 projection loops，不修改旧 Plan schema、操作意义或历史记录。

base 接受后、projectGroups 前另做 group preflight：groups.length 与 collapsedIds.length 各≤4096、所有 memberIds 长度累计≤20000（先按各数组 length 累加，到超限就停，未检查余项显示下界），最多20000 member visits，不先复制、去重或分配 aliases。沿用 loaded/intersect/首组规则求 exact visual node 数、保守 routeUpperBound；500 cards/2000 routes cap 与全局5000/20000独立。对现役成员 some/includes、每条 affected route 的成员/内部关系/port 扫描与临时 allocations，再使用保守 `groupStepsUpperBound = 64*(baseNodes+baseEdges+groupsScanned+collapsedIds.length+memberVisits+visualNodes+routeUpperBound) + 4*routeUpperBound*(baseNodes+baseEdges+visualNodes)`，cap **2000000 steps**；所有 header/member/route/internal-ID/port/notices entries 的保守分配上界≤10000。上界超限先拒绝，不能生成放大数组后再验证。preflight 自身无全 group×all edges 扫描：先建≤20000 membership entries，按≤2000 base edges 有界累加 1+g(source)+g(target)，触及2001即停；上界 labels 与 partial_lower_bound 同 base 契约。输入超限、实际工作上界或视觉放大拒绝必须区分理由，不能自动 collapse/persist group 状态。

**安全降级独立于被拒绝的层**：优先保留上一幅已接受、同project且明示旧snapshot/scope的安全图；若没有，且当前原始 graph 满足300/900，则重新调用 preflight(graph,[],fact,[])、projectGraph(graph,[],fact,positions)，**不传原 operations、references 或任何 groups，不调用 projectGroups**。这是 fact-only bounded fallback，最多300 emitted cards/900 raw relation candidates，notices≤900，projection work上界由独立空ops预检证明，不能复用已放大的 rejected base 或只改filter标签。若原graph自身超限/无可用graph/该预检拒绝，则保持空安全画布并提示范围未完成，不裁数据拼 ready。可呈现先前安全图的 group/plan 图仅因为它曾通过全部预算；不能重新跑被拒绝层来“降级”。fallback显示“计划/分组层未呈现；当前仅局部事实/先前范围”，不是本次 plan/group layout ready；不请求无界graph、不改editor/filter/collapsed状态/positions。

hidden/unknown members 不造假卡片，group mirror身份/首alias pin规则不变。visual route 上界文案明确“上界B/2000（尚未生成）”；early-stop 下界文案为“至少B/2000”，都不能伪报实际渲染数。

ProjectionEstimate early-stop 只填写 nodesLowerBound/edgesLowerBound；未完整求值的 nodes/edgeUpperBound 必须省略，不能把下界塞进上界字段或填0。完成拒绝可以另带 exact nodes/保守 edgeUpperBound，但 countStatus 必须 complete。visualAllocationsUpperBound 计当前 projection 的主要 list/map/set entries，group unknown member 的 Set/ids 数组、loaded arrays、affected/routes/internal IDs/ports 也包含，不能只数最后的 cards/edges；重复被 dedup 的源元素可按原length保守高估。preflight自身只使用前述明确受限的索引，不以预算名义先复制全Plan/全部membership/大bucket。实际字符串字节与既有大Plan HTTP读取不在此预算能力声明内，真实中型场景仍须按原计时门槛验收。

expanded group的**未固定**header/mirrors采用局部block，内部按global域rank/order行列，mirror同域id继承同rank但有独立位置；任何已固定member/header单独作为障碍并保持原坐标。header固定时，未固定成员block从其下方开始，必要时在同一scope空位移动；member固定在组外仍显示同一函数镜像badge，不为造“实体容器”移动它。shared member在多个组不是两份事实。routes位置使用原source/target/handle，方向约束按真实relationID+layoutunit pair去重，同一视觉重复route不增加权重；保留全部原证据/关系身份和collapsed ports，内部dependency不由membership生成。

全局worker未知尺寸的格点不能直接证明当前DOM无重叠；局部compact以实际尺寸做独立校正。只显示卡片才可用实际DOM尺寸；offscope尺寸未知，默认box不是实测。fallback：code300×220、group360×(220+60×portIds.length)。当前scope最多两次measurement-correction，每次最多500cards/2000routes；两次共用上表 local job 的 visits/comparisons/entries/diagnostics counters，第二次不能重新获得完整预算；测量变化≤1px忽略。第一次按fallback产生候选auto位置，第二次用全部已初始化的实际宽高修正并验证。候选结果先暂存，尺寸从既有projection当前渲染读取，不需先apply部分新layout；全部要求的校正及final validation完成后才一次apply/标ready，显式reflow也在此后保存。第二次耗尽预算不能apply/save第一次候选；保留原positions/安全画布。仍无法无自动重叠则明确geometry拒绝，不宣称零碰撞或无限effect循环。拖动期间不布局；theme/locale导致实际尺寸变化只能走这有界校正，不能保存自动结果或偷走camera。保守格点只给全项目未知尺寸模型；**几何零碰撞验收只针对当前实际测量scope与自动点**，不可宣称5000个未显示卡片都经DOM验收。

当前局部同步布局两次合计目标≤120ms，单帧最多500项位置apply；超时收据需修复/调低visual预算，不把120ms当已证实保证。只对scope/事实代次/plan projection/组collapse或membership/尺寸代次/显式reflow响应，不对pan/zoom/fitView每次运算。visible token为上述worker token再加 `{projectionGeneration,measurementGeneration}`，overlay plan revision、filter、reference anchors、group状态、导航scope变化都增projectionGeneration。旧scope/旧plan/旧measurement结果无效。

## 默认、手动与显式重排的保存合同

默认打开项目先正常加载保存的view/局部graph，后台获得完整layout-target与worker结果；未定位nodes自动呈现，所有saved positions优先。**默认auto不写ViewState**。全项目结果内存最多当前与上一个项目两份（各cap5000/20000），不存源码；project close/unmount释放worker和缓存。reload重新确定性计算auto位置，保存的手动点从SQLite恢复。相同snapshot与输入得到同auto布局；之后同projectrefresh保留存活auto点，不每刷新全重排。重新打开旧项目只保证saved点与确定性auto，不声称未保存临时自动点历史恢复。

保留既有“普通布局拖动→保存visual key”行为；新增 `saveLayoutPositions(patch:Record<string,XY>, capture:{projectId,snapshotId,projectionGeneration,viewGeneration})` 在**实际apply时读取当前view**并只merge位置patch，保留theme/locale/collapsedGroupIds/all offscope/unknown keys。传入capture不一致时拒绝，不拿旧render闭包的view覆盖新theme或拖动。沿用现saveView250ms scope-cancelled timer与serialized writes；递增viewGeneration在任何view修改前完成。layout helper不能直接putDB/调用updatePlan/approve。

overview有两个明确动作：

- “重算全项目自动布局”重新计算完整目标，不使用retained自动点，仍保留全部saved手动pins；新结果仍是derived，不写默认auto positions。超限/失败不改view。
- “重新排列当前视图”在当前overview的真实可见visual IDs上显式忽略pins，显示“替换本视图N个位置，其他位置保留”，完成有界测量校正后只merge这些IDs的新坐标并saveView；不清空整个positions。其结果作为用户显式选择的saved布局，以后与drag位置一样优先，无需origin schema。group首alias新key可覆盖其canonical fallback，但旧`fact:<domainId>`位置仍保留，不能删除隐藏canonical点或误更新原Node字段。scope/filter/groups/plan/view代次在测量期间变化即取消，不自动保存旧结果。

readonly布局没有新revision/history或批准失效；已有 `Knowledge.saveView`只写views。真实pointer drag、theme/collapse并发、更晚拖动/重排、HTTP失败后重试都要验证位置合并。view没有server CAS，多浏览器标签同时写仍是现有last-writer-wins；本票承诺当前单tab序列与作用域取消，不伪称跨tab事务。无ack时保留本地用户位置并提示未保存，不用服务返回旧view覆盖更晚本地修改。
