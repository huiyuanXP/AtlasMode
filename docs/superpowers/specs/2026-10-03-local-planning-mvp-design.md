## 架构与运行

遵守 README 的包边界：

| Workspace | 职责 | 内部依赖 |
| --- | --- | --- |
| packages/core | schema、纯规划规则、稳定 ID 约定、ports | 无 |
| packages/indexer | 文件扫描、TS/JS AST 与符号解析 | core |
| packages/storage | SQLite migrations 与持久化实现 | core |
| packages/service | 索引、规划、批准、路线与核对用例 | core，通过 ports 注入实现 |
| apps/server | HTTP、静态页面与实现装配 | core、service、indexer、storage |
| apps/web | React Flow 界面与 HTTP client | core |
| apps/mcp | stdio MCP 到 HTTP 的桥接 | core |

采用 Node 24 LTS、npm、一份根 package-lock.json。精确工具和依赖版本在实际安装
兼容性验证后锁定；不提前宣称未经安装的版本受支持。SQLite 使用 better-sqlite3，
优先可信预构建产物，需要时采用已提供的 Python/make/C++ 编译工具，不关闭校验。

生产模式：构建后启动一个本地服务，同时提供 UI 和 API，默认 loopback:4310。
开发模式：Vite:5173 代理 API 到该服务。MCP 由外部客户端启动 stdio 子进程，连接
同一 HTTP 服务。MCP 日志只写 stderr，stdout 只承载协议。

所有产品启动入口使用 Node/npm，不依赖用户拥有 Bash。处理 Windows 路径与路径
分隔符时采用 Node path API，模型内保存仓库相对 POSIX 路径。避免依赖 cwd 猜目标
仓库；支持 CODEMAP_WORKSPACE_ROOT、CODEMAP_DATA_DIR、CODEMAP_PORT 和 CODEMAP_API_URL。
默认目标可通过服务配置指定；用户也可在网页输入本地路径切换。每个请求指明
projectId，服务按对应项目根目录校验扫描与读取范围，拒绝越界路径和符号链接。
SQLite 和生成缓存不提交 Git。以用户已有 checkout 工作，不另建云端 worktree。

## 事实索引与浏览

索引由 ts-morph/TypeScript 提取，不由 LLM 猜测。解析函数声明、命名箭头/函数表达式、
类方法，记录签名、范围、导出状态、符号类别和证据。稳定 ID 由项目、相对路径、
限定名与声明类别组成，不以行号作为身份。匿名回调保留可说明的结构身份。

支持跨文件 import、别名和 re-export；记录可解析调用、外部包和 unresolved 原因。
Python 使用标准库 ast 在独立 Python 3.10+ 解析进程中读取，不执行目标项目的导入、
顶层代码或函数。支持模块/包相对导入、函数/类方法和可解析调用；动态派发无法
解析时明确标记。自动检测 python3、python、Windows py，允许 CODEMAP_PYTHON
显式指定。未安装 Python 时 TS/JS 功能仍可使用，但 Python 索引明确返回缺失依赖。
不能确定的动态调用保留可查询的未知记录，不假装不存在。快照记录纳入文件的内容
摘要、Git revision（存在时）、扫描范围、排除项与解析诊断。忽略 Git、依赖、构建
产物、缓存和 vendored 技能等与目标产品源码无关的明确排除路径。

默认入口以明确的源码导出/可识别注册证据为依据。区分“导出的入口候选”和已确认的
框架入口；不把无入边函数自动判成入口或死代码。第一屏展示入口及文件/目录上下文，
用户点击后逐步展开调用方/被调用方。入口、搜索、图查询采用分页/节点预算；不能
因预算限制静默丢弃扫描结果，UI 告知可继续展开。

中大型仓库不会默认渲染所有函数。搜索能定位到未在当前画布中的真实节点，展开后
显示实际端点及证据。刷新、缩放或布局操作不改变代码事实、用户知识或批准语义。

## 浏览路线接口

路线是独立知识记录，包含 id、snapshotId、revision、title、description、source
以及有顺序的 steps。每个步骤引用真实 nodeId，可携带说明及实际 relationId 证据。

- walkthrough：表达解释顺序，允许在不同文件/节点间跳转，不宣称步骤间存在调用。
- call_chain：步骤间需要有快照中的真实关系证据，否则拒绝或明确返回校验错误。

服务提供提交/读取/校验接口；MCP 复用同一入口，来源标为 Agent。UI 提供路线选择、
步骤列表和上一项/下一项，能聚焦对应节点。快照变化或节点失去绑定时提示路线过期，
保留原记录供检查，不悄悄删除或伪造迁移。此接口以后可被 skill 调用，但本轮不
执行未知第三方脚本或建立通用 skill 管理系统。

## 图上规划与确认

CodeSnapshot、Knowledge、PlanRevision 和 ViewState 分开存储。事实层不能被画布
编辑覆盖；修改事实箭头转化为规划中的删除/新增关系。新增函数使用临时 ID，必须
有明确目标文件。用户可以改接规划端点、删除多余辅助函数、编辑职责与复用说明。

每次语义更新提供 expectedRevision，服务拒绝并发覆盖。校验节点 ID、端点、关系
类型、相对目标路径、基线和明确约束；允许递归关系。接口兼容性证据不足时输出
“无法判定/需要适配”，不提供虚假的类型兼容结论。校验错误阻止确认，警告明确展示。

用户通过 UI 确认具体 revision、内容摘要与基线，审批和 revision/hash 在同一事务
保存。确认后修改目标文件、职责、依赖或约束会创建新版本并撤销旧确认有效性；仅
变动画布布局不撤销确认。目标内容改变后，Agent 读取批准版本时收到 valid=false
及原因，必须重新核对；原批准记录仍作为历史保留。

规划编辑与确认不自动写目标源码。本工具不能隔离拥有 shell/文件访问权的外部 Agent，
只提供可信数据与交互流程，不声称系统级禁止绕过。用户/Agent 之后按批准规划实施。

## MCP 与实现核对

稳定 MCP SDK 选一个经过官方 API 文档和实际测试的 major，不混用示例。
至少提供项目摘要、函数搜索/上下文、预算子图、路线提交/读取、规划提交/更新/校验、
批准版本读取、刷新索引和实现核对。规划与路线的写入均校验 revision/快照。

MCP 不提供用户批准工具，不接受伪造的 approved=true。UI、HTTP 与 MCP 读取同一
业务层和数据库，不重复实现规划/确认状态机。

结构核对基于一个确实存在的历史批准 revision 和新快照：匹配目标路径、限定符号
与声明类别，检查计划中的调用/复用关系。多候选、动态调用与信息不足输出无法判定，
明确区分 satisfied、unmet 和 unknown，并附代码证据。历史批准可用于核对已经实施
的变更；不能把实施产生的新快照倒说成原来的基线。结构符合不代表功能测试通过。

## 测试与验收

| 验收 | 失败条件与证据 |
| --- | --- |
| 安装/构建/类型/静态检查 | frozen 安装、build、typecheck、lint 的实际退出状态 |
| 真实索引 | fixture 的跨文件别名/re-export 调用缺失或错误；未知调用没有原因 |
| 稳定身份 | 插入空行后符号 ID 改变、注释失去绑定 |
| 路线 | 无效 nodeId、错误调用链或过期快照被静默接受 |
| 规划 | 改接 A 到 B、删除辅助节点、目标文件调整未准确保存 |
| 批准 | 并发 revision 被覆盖，语义变更仍有效，纯布局使确认失效 |
| 过期 | 未提交内容变化后，仍向 Agent 报告旧规划有效 |
| 持久化 | 重启丢失规划、批准、布局、注释或路线 |
| UI/MCP 一致 | 实际 stdio 客户端与 UI/API 读到不同 revision/hash |
| 实现核对 | 正确调用 B 未识别，故意绕过 B 未报告，未知被误报通过 |
| 本地运行 | 实际 HTTP 请求/页面功能失败；不能只以 PID 或端口算通过 |
| 浏览器/视觉 | 编辑动作失败、控制台错误、页面不可用或节点/连线明显遮挡 |
| 公开仓库 | 固定 tag/commit 与扫描范围下，真实索引/入口/搜索/展开失败 |

单元/集成测试遵循 TDD。浏览器检查至少覆盖入口选择、展开、搜索、规划节点/关系
编辑、确认失效、路线浏览和重启恢复；保存截图并实际查看代表页面，不能只检查
截图文件存在。截图和运行报告属于 artifacts，不提交目标仓库源码副本或数据库。

为 CI 配置 ubuntu/windows/macos 的安装、类型检查、单元/集成、构建和本地服务 smoke
矩阵；浏览器 E2E 至少在 Linux runner 执行。实际能启动哪个 runner，就记录哪个的
结果。当前云端是 Linux，未经 native runner 的 Windows/macOS 结果写“未执行”，
不能把 YAML 配置当作通过。无远端运行授权/能力时，完成本地 CI 等价命令和矩阵
配置，清楚报告远端尚未执行。

公开仓库候选为 Vite 的稳定发布，已确认有 v8.3.2 tag；实际取用时核对完整 commit。
测试目标放在 AtlasMode checkout 外。报告文件/函数/关系/未知数量、耗时和抽查
证据；若仅验证特定源码范围，明确范围，不宣称全仓覆盖或 Vite 自身测试已通过。
