# GRP-02 功能集折叠与真实外部端点

目标：功能集能在画布折叠/展开，保留真实外部函数端点及关系证据；同一函数属于多个组不丢失；刷新恢复折叠与布局。不移源码、不实施规划、不扩sequence/wrapper。

## 投影与重叠语义

底层CodeSnapshot及FunctionGroup.memberIds仍为权威，数据node.parentId及源码归属不改。基础projectGraph先产生现有事实/规划图，再由独立projectGroups纯函数生成视图。每个组有group:<groupId>卡片；展开成员为group-member:<groupId>:<domainId>视觉alias，data.node仍原真实函数。卡片明确“同一函数的分组镜像”和所在组、源文件，不能看起来像新增源码。被组表示的已加载真实函数不再重复canonical卡片；未分组节点保留原视觉ID。

成员多对多：每个所属组都拥有独立alias；折叠组以同一真实函数的source/target handle替代alias。没有单一业务parentId。每真实关系先生成确定主route（稳定按groupId优先），再为每相关组生成局部route（该组成员端点用本组alias/port，其余端点用主代表）；相同source/target/handles的route去重。避免重叠组笛卡尔N²边。多个route明确标注“同一关系的分组镜像”，保持同一domain relationID/真实sourceId,targetId与evidence；真实边既不新建也不丢弃。两个端点在同一个折叠卡片的内部route不画自环，已加载内部真实relationIDs去重计数；在另一重叠组对外的同一关系仍保留route。

折叠卡片显示loaded/总memberIds数、未加载/缺失未判定数、仅当前已加载内部关系数；端口显示对应真实函数名字和文件路径。数据不足只说明当前范围，不把未加载邻域当完整。external/unresolved关系继续沿用基础projection的通知，不构造虚假端点。

## 交互

卡片/组面板均可切换折叠。groupcard本身不作为可规划函数；别名点击/hover/focus、源码查看、规划关系仍使用data.node.domainID和原filePath。折叠外部镜像边不可拖动改接到聚合ID；点击显示真实source/target名称、文件:行、原evidence text、relationID，并可跳到两端真实函数检查。不会把visualID传给HTTP。

圈选和漏斗临时使用原基础投影，恢复时回到persisted折叠视图；圈选不把组卡/镜像重复算新成员。保留普通自由拖动、Esc链、首用行为。

## 持久化

ViewState新增optional collapsedGroupIds:string[]；老ViewState无字段保持兼容，默认展开。HTTP与Knowledge双边界校验最多200条、每ID1–200字符，去重；读写都过滤当前project实际groups，未知/旧/foreignID忽略，不影响另一project。JSON storage不迁移。groupcard/alias坐标复用positions，折叠是视图操作、不产生知识/规划语义改变或批准失效。

## 验收与边界

纯投影测多对多alias、折叠端口真实端点、relationID/evidence不丢、内部计数、计划层、unknownloaded范围、linear镜像去重和输入不变。Knowledge/HTTP测旧ViewState、边界/去重/project隔离、真实SQLite新实例恢复。Workspace测折叠保存与切换、视图不改approval。实际Chromium建立共享函数G1/G2，折叠一组与两组、展开、点外部调用证据/原源码、拖动卡片布局、刷新/ownedserver重启保持、圈选回归，逐字节源路径保持。rootfullbuild/test由主控协调，不commit/push/deploy。

自审：别名只改变视觉归属，端口携带真实函数身份；同关系多route有明确镜像标签且规模线性；未知邻域明示；旧schema兼容；三层core/server/service最小optional接口变更需要协调buildslot。

独立设计审修正：基础edge构造携带真实sourceId/targetId/evidence；inspection.ts及groups/inspection.test.ts采用真实domain端点及所有alias/折叠组代表解析方向/高亮；focusTargets及详情定位解析组内domain成员。

## 实施审查修订：局部范围及实际投影预算

独立代码审查 I1：只把至少一个真实成员出现在当前 base function nodes 的组投影到画布。全部组继续在 GroupsPanel 可管理，未显示组的 collapsedGroupIds/positions 不删除；活跃组仍报告 loaded/total/unknown。单函数局部图不会被 50 个范围外空组改变 fitView。

基础事实 budget 只约束事实图，不包含额外视图镜像。设 N 为基础节点数，U 为已归组真实函数数，G 为与加载范围相交的组数，M_expanded 为展开组已加载成员数总和，则投影节点数严格为 N−U+G+M_expanded。每条原关系最多产生 1+g(source)+g(target) 条视觉 route（同一关系内去重及折叠内部自环隐藏会减少），E' ≤ Σ_e(1+g(source_e)+g(target_e))。存储组数无独立硬上限，故这是按实际已加载 membership 的线性界，而非固定 300 视图节点上限；没有 N² 组交叉路由，不宣称全项目邻域完整。15 组交叠回归对内部/外部关系分别15条，50范围外组回归零额外alias/cards。
