## 问题与交付标准

当前 P0 仅有手写 demo 和健康检查，不能算第一版交付。第一版必须对授权目标仓库自动遍历并索引真实 TS/JS/TSX/JSX，生成可查询图，在网页和 MCP 中使用同一份数据，提供规划及知识记录的完整增删改查，并保留确认/版本/基线语义。

## 验收

- [ ] 目标仓库配置固定，启动自动索引，刷新能反映源码新增、修改、删除；排除依赖、构建、缓存和越界路径。
- [ ] 函数/方法、目录/文件、导入、可解析调用来自真实源码；动态调用明确 unresolved。
- [ ] 网页能搜索、查看上下文和有预算的子图，显示来源/证据/未知项。
- [ ] 注释、功能集、目录规则、布局可增删改查，重启/重索引不丢失；孤立引用保留待重新绑定。
- [ ] 规划节点/关系/目标文件可增删改查，使用 expectedRevision；事实与规划分层。
- [ ] UI 人工确认绑定 revision/hash/baseline，语义修改撤销确认，布局修改不撤销，过期基线阻止实施。
- [ ] stdio MCP 提供 README 中的查询、规划、分组、刷新与核对工具，不提供冒充用户审批的工具。
- [ ] 完成 fetchNotes → requestWithRetry 的真实跨文件闭环，并识别故意绕过该抽象的实现偏差。
- [ ] 锁定安装、类型、lint、单元/集成/MCP/浏览器检查通过；文档明确实际能力与限制。

## 边界

保留单用户/单目标仓库；只监听 loopback；不承诺系统级 shell 写入隔离。CRUD 作用于规划和知识：真实代码事实由解析器生成，编辑事实转成规划，不伪造解析结果。源文件实施由读取有效已确认版本的外部 Agent 完成。
