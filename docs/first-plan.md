# 用 AtlasMode 做第一份规划

先在仓库根目录安装并启动：

```text
npm ci
npm run build
npm start
```

使用仓库固定的 Node24.19.0/npm11.9.0；分析 Python 时需 Python3.10+。
打开 `http://127.0.0.1:4310`。本机安装、数据目录和检查命令见
[environment.md](environment.md)；Agent 连接见 [mcp.md](mcp.md)。

## 浏览真实代码

1. 点击“打开项目”，在对话框的“本地项目路径”输入目标目录的绝对路径，点击“打开并索引”。路径属于运行
   AtlasMode 服务的机器，例如 Windows 的 `C:\work\project` 或 macOS 的
   `/Users/me/work/project`。已经打开的项目可在“切换项目”中选择。
2. 左侧直接搜索函数，或展开“浏览代码”选择入口候选。悬停预览关联，单击卡片打开引用详情；
   调用行显示函数名称、文件与证据行号，可预览唯一关系并跳转目标。文件详情按页列出声明、跨文件调用与导入。
   “查看源码”显式展开源码；画布上方面包屑显示项目到函数的路径，每级均可点击跳转。
3. 双击函数/文件进入动画漏斗：依赖它的内容在上方、当前对象独自在中间、其依赖在下方；
   无关卡片保留在侧边。所有卡片可拖动，漏斗位移按根节点临时保存，“重新排列”恢复当前漏斗布局。
   小地图可展开定位、拖动视口与缩放，空间受限时暂收详情并在地图收起后恢复；Esc 依次收起小地图、关闭详情、退出漏斗，退出后恢复普通布局。
   源码面板“展开一层”也可继续浏览。每次默认最多
   80节点/240关系，截断时可缩小范围或扩大至300/900。“未解析”表示证据不足。
4. Agent 提出的多条“浏览路线”出现在左侧展开的“浏览代码”中。选择路线后逐步聚焦；调用链有真实
   调用证据，讲解路线表示解释顺序。过期路线需要重新提交，不能继续当成新事实。

入口是静态候选：TS/JS显式导出、Python顶层公开命名；不等于运行时确认的API。
解析范围和未完成的模块类型见 [要求覆盖表](superpowers/readme-coverage.md)。

## 通过 Chat 规划改动

连接方式见 [Agent Chat](agent-chat.md)。左侧可以询问“这个请求流程从哪里开始”，右侧可以输入“添加 fetchNotes，复用现有 requestWithRetry”。Agent 通过真实 MCP 读取代码并提交未批准规划，完成后镜头自动聚焦新增或修改内容。右侧固定“待你审查 · N”，点击“查看改动”进入变更、校验、导出和独立确认；逐项选择变更可聚焦对应图对象。聊天框按项目和探索/规划频道隔离；可停止运行，中途已保存的规划仍会重新读取。

已有 Profile/API 环境可以直接使用，无需重新 Device 登录；独立 API 适配器尚待 AG-05。Chat 当前可浏览和修改规划，源码实施模式是 AG-02，不能把规划草稿当成已修改源码。

## 高级编辑与手动调整

通过“高级编辑”打开原有表单；它们默认收起。以下是仍可使用的精确编辑入口：

1. 在高级编辑中输入“新规划标题”并“创建规划”。将显示层选为
   “事实 + 规划”，对照当前代码和拟议修改。
2. “新增规划函数”填写函数名、仓库相对目标文件、签名和职责。目标文件可以尚未
   存在，例如 `src/services/retry.ts`；这一步保存意图，不会写入目标代码。
3. 点击已有调用箭头，选择新的目标并“保存改接关系”。若目标还未出现，先搜索
   它；同一快照已加载的搜索/入口候选也可选。已有事实箭头的改接会保存删除旧关系
   和新增关系的规划操作。新增关系可选择“调用”“必须调用”或“必须复用”。
4. 选中规划函数可修改目标文件和说明，或“删除临时函数及其规划边”。“添加说明”
   保存约束文本，不产生调用。右侧“变更清单”可以移除不需要的操作。
5. 在“功能分组”展开“已选成员”，勾选事实函数并创建分组；“目录职责”填写目录
   职责和明确的禁止依赖。知识修改会使这个项目的当前规划需要重新确认。
6. 使用“撤销”“重做”调整语义编辑。每个规划最多50步、保留20个规划；页面重载
   清空撤销栈，已保存规划和批准历史继续在SQLite中保留。画布拖动只保存布局。

删除目标后，依附它的说明仍可能保留并显示失去绑定。请检查校验结果和对应操作，
主动决定重新关联或移除说明；程序不会静默丢弃你的约束。

## 确认、导出和核对

点击“校验规划”，阅读服务端结果。调用兼容性没有充分证据时会提示需要检查或
适配；这种警告允许继续确认，代表结构规则通过而非参数/类型已经验证。

检查完“变更清单”后点击“确认此规划”（高级编辑保留“确认当前 revision”）。确认绑定当前版本、摘要和基线；
语义或知识编辑使批准失效，普通布局变化不影响批准。JSON和Markdown按钮导出
同一份规划，方便交给Agent或人工阅读。

Agent实现后点击“刷新代码”，再“核对已批准实现”。核对使用最近已批准的历史
版本，并显示“已满足”“未满足”“无法判定”及源码证据。被忽略/不可读的原文件
不能当作已删除，同名替代不能自动证明复用；结果不替代目标项目自身的行为测试。

## 给 Agent 的第一条指令

配置并连接MCP后，可以使用下面这段：

```text
请使用 AtlasMode 的 MCP：先 list_projects 并确认我网页中打开的 projectId；
读取 get_project_summary、搜索和调用上下文。先提出几条有明确说明的浏览路线，
再基于当前 baselineSnapshotId 提交规划，明确函数、目标文件、复用对象和说明。
在我通过网页确认之前等待，不修改目标代码。确认后读取 get_approved_plan，
核对有效性、revision和hash，再按照该版本实施。完成后重新索引并核对实现，
解释 unmet/unknown，不把没有证据的关系当作已经满足。
```

AtlasMode核心在安装后使用本机服务；模型联网由Agent客户端负责。MCP和网页
共享数据，MCP没有批准工具。实际Codex/Claude客户端会话及原生Win/mac运行的
验证状态仍以 [environment.md](environment.md) 为准。
